# cRSI (RSI Cyclic Smoothed)

트레이딩뷰용 Pine Script 보조 지표 설명서입니다.

대상 스크립트:
- [`rsi-cyclic-smoothed.pine`](./rsi-cyclic-smoothed.pine)

> Pine Script **v6** 기준입니다(v4에서 마이그레이션, 신호·계산·파라미터 동작은 동일하게 보존).

이 지표는 기본 `RSI`에 **지배 사이클(Dominant Cycle)** 기반의 평활화와 **동적 과매수/과매도 밴드**를 더한 버전입니다. 고정된 `30 / 70` 기준 대신, 최근 사이클 구간에서 cRSI가 실제로 머문 범위를 기준으로 상·하단 밴드를 계산해 줍니다. 원작은 Lars von Thienen의 *Decoding The Hidden Market Rhythm*(2017) 4장에서 소개된 cRSI입니다.

## 현재 소스 기준으로 보이는 것

| 요소 | 현재 표시 방식 |
| --- | --- |
| CRSI (기본 차분한 골드 선) | 사이클로 평활화한 RSI 본선입니다. 하늘색 밴드와 대비되도록 기본 차분한 골드(`#E6B800`, 밝은 노랑보다 명도·채도를 낮춘 골드 톤)로 표시하며, `선 색상` 그룹의 `cRSI 선 색` 입력으로 원하는 색을 고를 수 있습니다. 노랑 계열은 주황(수축) 배경과 색상이 인접하므로, 수축 구간에서는 배경 대비가 다소 약해질 수 있습니다. |
| HighBand / LowBand (기본 밝은 하늘색/시안 선) | 최근 사이클 메모리 구간에서 동적으로 계산한 과매수/과매도 밴드입니다. 상·하단 모두 기본 밝은 하늘색/시안(`#4DD0E1`, Material Cyan 300 계열)으로 표시하며, `선 색상` 그룹의 `상단밴드(HighBand) 색`·`하단밴드(LowBand) 색` 입력으로 각각 원하는 색을 고를 수 있습니다. **밴드 상·하단(HighBand/LowBand) 값은 우측 프라이스 스케일(가격 축) 라벨에 표시됩니다.** |
| 과매도/과매수 참고 점선 (은색) | 참고용 고정 기준선입니다. 기본 `30`(과매도)·`70`(과매수)이며, `참고 레벨` 그룹의 `과매도 참고 레벨`·`과매수 참고 레벨` 입력으로 조정할 수 있습니다(참고 점선 표시 전용입니다). |
| Band Width Background | 밴드폭이 좁으면 진한 주황색(수축), 넓으면 보라색(확장) 배경으로 강조합니다. 불투명성 기본 15(0=투명, 100=진함)로 연하게 깔립니다. |
| 밴드 교차 가격 테이블 (기본 우측 상단) | 기준봉(`테이블 기준봉` 설정 — 기본 **실시간봉**=차트 마지막 봉 `[0]`, 틱마다 갱신 / **완성봉**=가장 최근 완성봉, 고정) 데이터로 역산한 "다음 봉이 이 종가로 마감하면 cRSI가 밴드를 넘나드는" 조건 가격 4행(`상단 돌파`/`상단 이탈`/`하단 돌파`/`하단 이탈`). 아래 "밴드 교차 가격 테이블" 항목 참고. **종가 기준 조건 가격이며 매매 신호가 아닙니다.** |

참고(축 라벨 표시):
- 우측 **프라이스 스케일(가격 축) 라벨에는 CRSI 본선 값과 함께 밴드 상·하단(HighBand/LowBand) 값**이 표시됩니다. 현재 과매수/과매도 경계가 축에서 바로 읽힙니다.

참고:
- 기본값은 `Dominant Cycle Length = 20`이며, 내부적으로 RSI 길이 `cyclelen = 10`, 사이클 메모리 `cyclicmemory = 40`으로 환산됩니다.
- `vibration = 10`, `leveling = 10.0`은 코드 내부 상수로 고정되어 있습니다(입력값 아님).
- 동적 밴드는 사이클 메모리(`40봉`) 구간에서 cRSI 값의 분포를 백분위로 훑어, 하위 `10%`(LowBand)·상위 `10%`(HighBand) 경계를 잡습니다.
- 밴드폭 배경은 `bar_index < cyclicmemory`(초기 구간)에서는 표시되지 않습니다.

## cRSI를 쓰는 이유

일반 RSI는 `30 / 70` 같은 고정 기준을 쓰지만, 종목·국면에 따라 RSI가 실제로 도는 범위가 다릅니다.

- 추세장에서는 RSI가 한쪽에 쏠려 `70`을 계속 넘겨도 과매수로 보기 애매합니다.
- 횡보장에서는 `30 / 70`에 닿기 전에 이미 반전하기도 합니다.

cRSI는 사이클로 평활화해 노이즈를 줄이고, **최근 구간에서 cRSI가 실제로 머문 범위**로 밴드를 그려 "지금 국면 기준으로 과한지"를 봅니다.

## 트레이딩 의미 핵심

### 1. cRSI가 LowBand 아래일 때

`최근 사이클 기준으로도 과하게 눌린 구간`을 뜻합니다.

- 고정 `30`보다 그 국면에 맞는 과매도 경계라서, 횡보·추세 양쪽에서 더 현실적인 자리로 봅니다.
- 단독 진입보다는 `되돌림 감시 자리`로 보는 편이 맞습니다.

### 2. cRSI가 HighBand 위일 때

`최근 사이클 기준으로도 과하게 올라간 구간`을 뜻합니다.

- 급등 뒤 상승 피로를 보는 데 유용합니다.
- 메인 신호가 약해지는 자리와 겹치면 `후행 롱 자제`, `숏 감시` 의미가 커집니다.

### 3. 밴드폭 배경(진한 주황색 / 보라)

밴드폭(`HighBand - LowBand`)은 변동성/사이클 진폭의 대리 지표입니다.

- **진한 주황색(좁은 밴드)**: cRSI가 좁은 범위에서만 움직이는 `수축 구간`. 큰 움직임 직전의 눌림일 수 있어, 밴드 돌파 방향을 주시합니다.
- **보라(넓은 밴드)**: cRSI가 크게 출렁이는 `확장 구간`. 신호가 자주 극단에 닿으므로 과매수/과매도 신호의 신뢰도를 한 번 더 거릅니다.

## 내부 로직

1. `cyclelen = domcycle / 2` 길이로 기본 RSI를 계산합니다.
2. `torque`, `phasingLag`(vibration 기반)로 cRSI를 사이클 평활화합니다.
   - `crsi := torque * (2*rsi - rsi[phasingLag]) + (1 - torque) * crsi[1]`
3. 최근 `cyclicmemory(= domcycle * 2)`봉 구간에서 cRSI의 최댓값/최솟값을 찾습니다.
4. 그 범위를 100단계로 나눠, 분포의 하위 `leveling%`(LowBand)·상위 `leveling%`(HighBand) 경계를 백분위로 잡습니다.
5. 밴드폭으로 배경색(수축/확장)을 칠합니다.

즉 고정 임계선이 아니라, `현재 국면에서 cRSI가 실제로 돈 범위`를 기준으로 과매수/과매도를 판단하는 방식입니다.

> 기존 우측 상단 **cRSI 상태판**(`포지션`·`cRSI 값(밴드폭)`·`모멘텀` 3행)은 CEO 지시로 **제거**되었습니다. 상태판 전용 판정 로직(수축 돌파 지속 래치 `crsiBreak`, 확장 다이버전스 래치 `crsiDiv`, 모멘텀 5분류 `crsiSlope`/`slopeEps`, `포지션` 판정)도 함께 삭제됐으며, 차트 마커·배경·밴드 동작은 변하지 않습니다. 밴드폭 수축/확장 상태는 배경색으로, 확장 다이버전스는 ▲▼ 마커로 확인합니다. 이제 차트의 테이블은 아래 **밴드 교차 가격 테이블** 하나뿐입니다.

## 밴드 교차 가격 테이블

기본 **우측 상단**(auto-vwap 테이블과 같은 위치)에 헤더 없는 4행 테이블이 표시됩니다. 각 행은 "**다음 봉(형성 중이거나 다음에 올 봉)이 이 종가로 마감하면** cRSI가 해당 밴드 조건을 만족하는 경계 가격"이며, 2열에 `가격 (기준봉 종가 대비 부호 포함 %)` 형식으로 표시합니다 — 예: `12,345.6 (+2.3%)`. 기준봉은 `테이블 기준봉` 설정(기본 `실시간봉`)으로 고릅니다(아래 "기준봉 선택" 참고).

- **가격 포맷**: 천 단위 쉼표 + 종목 `syminfo.mintick` 소수 자릿수(예: `1,000` / `12,345.6` / 틱 0.25 종목 `12,345.25`). auto-vwap의 `#,##0.0…` 포맷 방식과 같으며, 자릿수는 `mintick × 10^d`가 정수가 되는 최소 `d`(최대 8)로 정해 0.25·0.005 같은 틱도 자릿수가 잘리지 않습니다. %는 **소수 1자리** 부호 포함 `(+2.3%)`이며, 반올림 결과가 0이면 `0.0%`로 표시합니다(`-0.0%` 방지).
- **행 배경색**: `상단 돌파`·`하단 돌파` 행=녹색 `#2E7D32`, `상단 이탈`·`하단 이탈` 행=적색 `#C62828`(펀드 공용 녹/적 팔레트), 흰 글자. **모든 셀 배경과 테두리는 불투명(투명도 0)** 이며, 위계는 투명도 대신 단색 톤 차이로 표현합니다 — 라벨 셀=기본색(녹 `#2E7D32`/적 `#C62828`), 값 셀=한 톤 밝은 동계열(녹 `#388E3C`/적 `#D32F2F`). 값이 `-`인 비활성 행은 어두운 저채도 톤(녹 라벨 `#1B3A1E`·값 `#142B17` / 적 라벨 `#3E1A1A`·값 `#2E1414`)에 회색 글자(`#9E9E9E`)로 낮춰 현재 상태에서 의미 있는 행이 눈에 띕니다(`도달불가`는 활성 행으로 취급). 테두리는 불투명 회색 `#555555`.
- **노란 굵은 글자(특수 상황 하이라이트)**: 행 종류 기준 일반 규칙입니다. **돌파 행(`상단 돌파`·`하단 돌파`) 값이 `−%`**, **이탈 행(`상단 이탈`·`하단 이탈`) 값이 `+%`**이면 값 셀 글자를 흰색 대신 순수 노랑 `#FFFF00` + **굵게**(`text.format_bold`)로 표시합니다(배경색은 그대로, 하이라이트 셀만 굵게). **보합 또는 역방향 소폭 움직임만으로도 다음 봉에 해당 교차가 일어나는**, 즉 다음 봉에 그 액션이 나올 가능성이 높은 상황입니다. 판정은 틱 반올림 가격과 기준봉 종가의 실제 부호로 하되, 표시 %가 반올림으로 `0.0%`가 되면 하이라이트하지 않아 표시와 색이 항상 일치합니다. `-`·`도달불가` 셀은 대상이 아닙니다. 대비비(WCAG): 녹 값 `#388E3C` 위 3.83:1, 적 값 `#D32F2F` 위 4.64:1.

> **종가 기준 조건 가격이며 매매 신호가 아닙니다.** 장중 가격이 이 값을 스쳐도, 봉 마감 종가가 조건을 충족해야 cRSI가 실제로 밴드를 넘습니다. 이치모쿠·테이블·타 보조지표 정렬 확인용 참고값으로만 씁니다.

| 행 | 의미 (다음 봉 종가 조건) | 값이 표시되는 상태(기준봉 = `테이블 기준봉` 설정의 봉, 오프셋 `k`) |
| --- | --- | --- |
| `상단 돌파` | 종가 ≥ 이 가격 → cRSI ≥ 상단밴드(ub) | 중간(밴드 안) |
| `상단 이탈` | 종가 ≤ 이 가격 → cRSI < 상단밴드(밴드 안 복귀) | 상단 위(`crsi[k] >= ub[k]`) |
| `하단 돌파` | 종가 ≥ 이 가격 → cRSI > 하단밴드(밴드 안 복귀) | 하단 아래(`crsi[k] <= db[k]`) |
| `하단 이탈` | 종가 ≤ 이 가격 → cRSI ≤ 하단밴드(db) | 중간(밴드 안) |

- **상태별 표시**: 하단 아래 → `하단 돌파`만, 중간 → `상단 돌파`·`하단 이탈`만, 상단 위 → `상단 이탈`만 값을 보이고 나머지 행은 `-`입니다. 초기 봉 등 준비가 안 된 구간(`bar_index − k < cyclicmemory + cyclelen + phasingLag` 또는 값 없음)은 4행 모두 `-`입니다.
- **`-`**: 해당 상태에서 의미 없는 행이거나, 계산 데이터가 없음(기준봉 `up`·`down`이 모두 0 등).
- **`도달불가`**: 목표 cRSI를 만들 RSI가 0 이하·100 이상이 필요하거나, 역산 가격이 0 이하라 **어떤 종가로도 목표봉(다음 봉)에서 도달할 수 없는** 경우입니다. 또한 틱 반올림 가격의 기준봉 종가 대비 변동률이 **±100% 초과**(표시 % 기준 — `+100.0%`까지는 표시, `+100.1%` 이상은 `도달불가`)인 경우도 현실적으로 도달할 수 없는 값으로 보고 `도달불가`로 표시합니다(−100% 초과는 가격 ≤ 0이라 위 규칙에 이미 포함).
- **부호**: 계산값 그대로 표시합니다. cRSI 평활 관성 때문에 돌파 행이 `−%`(예: `하단 돌파` — 더 내려도 복귀, `상단 돌파` — 더 내려도 돌파), 이탈 행이 `+%`(예: `상단 이탈` — 더 올라도 이탈, `하단 이탈` — 더 올라도 이탈)로 나올 수 있으며 정상입니다(기준봉 cRSI 항 `(1−τ)·crsi[k]`와 위상 지연 RSI 항 때문에 보합만으로도 교차가 일어나는 경우 — 무작위 가격 시뮬레이션에서 해당 상태의 약 13~14%). 기준봉 버그 수정과 무관하게 남는 수학적 정상 케이스이며, 이런 경우는 노란 굵은 글자로 강조됩니다(위 참조).
- **틱 반올림**(`syminfo.mintick`): 조건을 확실히 만족하는 쪽으로 맞춥니다 — `상단 돌파` 올림, `하단 이탈` 내림, `상단 이탈` 내림(정확히 틱 위면 −1틱, 엄격 `<`), `하단 돌파` 올림(정확히 틱 위면 +1틱, 엄격 `>`). %는 반올림된 가격 기준입니다.
- **기준봉 선택 (`테이블 기준봉`, 기본 `실시간봉`)**: 두 모드는 기준 오프셋 `k`만 다르고 역산식·틱 반올림·`도달불가`·하이라이트·색·포맷은 동일합니다.
  - **`실시간봉`(기본)** → 항상 `k = 0`: 차트의 마지막 봉 `[0]`(형성 중이면 형성 중 봉)이 기준봉. 상태는 `crsi[0]` vs `db[0]`/`ub[0]`로 판정해 **차트에 보이는 현재 cRSI 위치와 일치**하고, 가격은 "**다음 봉** 종가가 얼마면 교차하는가", %는 현재 봉 `close[0]` 대비입니다. 형성 중 봉에서는 **틱마다 값이 바뀝니다(의도된 리얼타임 리페인팅)**. 봉 마감 시점(마지막 틱)의 값은 `완성봉` 모드에서 그 봉을 기준봉으로 삼은 값(`k = 0`)과 같습니다.
  - **`완성봉`** → 아래 시간 기준 판정의 `k`(0 또는 1): 가장 최근 완성봉 기준, 형성 중 봉의 틱 변동에 값 고정(리페인팅 없음). 이전 버전의 기본 동작입니다.
  - **주의**: 기본값이 `실시간봉`이므로 **"리페인팅 없음"은 더 이상 기본 동작이 아닙니다.** 고정된 값이 필요하면 `완성봉`을 선택하세요.
- **`완성봉` 모드의 기준봉 = 가장 최근 완성봉 (시간 기준 판정)**: 마지막 봉이 끝났는지를 `barClosed = time_close가 있으면 timenow ≥ time_close, 없으면 barstate.isconfirmed`로 판정하고, 기준 오프셋 `k = (barClosed 또는 barstate.isconfirmed) ? 0 : 1`.
  - **실시간(마지막 봉 형성 중, `timenow < time_close`)** → `k = 1`: 직전봉이 기준봉, 형성 중인 현재봉이 목표봉.
  - **마지막 봉이 이미 끝남**(바 리플레이, 장 마감 후 로드, 과거 데이터의 마지막 봉) → `k = 0`: 그 마지막 봉이 기준봉, **다음에 올 봉**이 목표봉.
  - **바 리플레이**: 리플레이로 새로 나타난 마지막 봉은 Pine 실행 모델상 *실시간 봉*으로 처리되어 다음 스텝 전까지 `barstate.isconfirmed = false`입니다. 이전 버전(`k = barstate.isconfirmed ? 0 : 1`)은 그래서 리플레이에서 `k = 1`이 되어 **이미 지나간 직전봉 기준**(예: 직전봉 하단 아래 → 마지막봉에서 밴드 안으로 복귀했는데도 `하단 돌파`만 표시)을 보여주는 버그가 있었고, `timenow`(실제 현재 시각)가 리플레이 봉의 `time_close`보다 항상 크다는 점을 이용해 수정했습니다.
  - **트레이드오프 — 리플레이 간격(update interval)을 차트 주기보다 짧게 둔 경우**(예: 1시간 봉을 1분 간격으로 재생): 그 봉도 `k = 0`이 되어, 봉이 다 그려지기 전의 값으로 계산되고 **스텝마다 테이블 값이 움직입니다**(리플레이 한정 리페인팅). 간격을 차트 주기와 같게(기본 "자동") 두면 매 스텝이 완성봉이므로 문제없습니다.
  - **`time_close`가 없는 차트**(틱·레인지·렌코 등 가격 기반 차트의 열린 실시간 봉): 시간 판정을 쓸 수 없어 `barstate.isconfirmed`로 폴백합니다(이전과 동일 동작).
  - 실시간 봉의 마감 틱에서 순간적으로 `k = 0`이 되는 것은 그 순간 그 봉이 완성봉이므로 정합이며, 다음 봉이 열리면 `k = 1`로 같은 기준봉을 가리켜 값이 이어집니다.
  - 참고: `timenow`는 스크립트가 실행될 때만 갱신됩니다. 장중에 차트를 연 채 장이 끝나고 마감 시각 이후 틱이 하나도 오지 않으면 스크립트가 다시 실행되지 않아 `k = 1` 표시가 남을 수 있습니다. 이때 차트를 새로고침(또는 설정 변경)하면 `k = 0`으로 다시 계산됩니다. 마감 시각 이후 틱이 한 번이라도 오면 확정 이벤트를 기다리지 않고 바로 `k = 0`이 됩니다.
- **리페인팅 없음(`완성봉` 모드 한정)**: 형성 중인 봉의 값(`close`·`crsi[0]`·`ub[0]`·`db[0]`, `k = 1`일 때)을 쓰지 않고 기준봉까지의 확정값(`up[k]`, `down[k]`, `crsi[k..k+cyclicmemory−2]`, `rsi[phasingLag+k−1]`, `close[k]`)만 쓰므로 **형성 중인 봉의 틱 변동에 값이 고정**됩니다. `실시간봉` 모드는 `k = 0`이므로 형성 중 봉의 `close`·`crsi[0]`·`ub[0]`·`db[0]`·`up[0]`·`down[0]`을 그대로 써서 틱마다 갱신됩니다.

계산 방식(알고리즘 수학자 확정 사양):
1. **목표 cRSI**: `ub[k]`/`db[k]`이 아니라 목표봉 기준 직전 `cyclicmemory−1`개 cRSI(`crsi[m+k−1]`, m=1..cyclicmemory−1, 분모 cyclicmemory)로 기존 밴드와 같은 백분위 격자를 돌려 얻은 정확 임계값 `U*`/`D*`를 씁니다(목표봉 cRSI ≥ ub ⇔ ≥ U*, ≤ db ⇔ ≤ D* 동치, brute-force 검증).
2. **목표 RSI**: `crsi = τ·(2·rsi − rsi[phasingLag]) + (1−τ)·crsi[1]`을 목표봉 기준으로 옮겨 rsi에 대해 역산 → `r* = ((T − (1−τ)·crsi[k]) / τ + rsi[phasingLag+k−1]) / 2` (`k = 1`이면 기존 `crsi[1]`·`rsi[phasingLag]`와 동일).
3. **목표 종가**: `rma` 갱신식(`up[k]`/`down[k]`, 길이 `cyclelen`)을 가격 변화 Δ에 대해 역산 → `P = close[k] + Δ`. %는 기준 종가 `close[k]` 대비입니다.
4. 무거운 루프(약 2×101×39회)는 마지막 봉(`barstate.islast`)에서만 돕니다.

## 돌파 원 마커(골든/데드) — 제거됨

> 밴드폭 수축(주황) 구간의 **골든/데드 크로스 원 마커**(cRSI가 상단밴드 상향 돌파=녹색 원, 하단밴드 하향 돌파=빨강 원)는 CEO 지시로 **전면 제거**되었습니다. 표시(원 마커 2개 플롯)·옵션(`수축 돌파 원 마커 표시` 토글, `수축 돌파 마커` 그룹)·판정 로직(`narrowBw`, `newNarrow`, `rawGolden`/`rawDead`, `goldenBreak`/`deadBreak`, 구간당 1회 래치 `goldenFiredNarrow`/`deadFiredNarrow`)이 함께 삭제됐습니다. 그에 앞서 확장(보라) 구간의 돌파 원 마커도 이미 제거되어 있었습니다. 밴드폭 배경(주황/보라)·확장 다이버전스 ▲▼ 마커·밴드 교차 가격 테이블 동작은 변하지 않습니다. 과매도/과매수 참고 점선 레벨 입력은 `참고 레벨` 그룹으로 옮겨졌습니다(값·동작 동일).

## 자주 만지는 설정

| 설정 | 언제 조정하나 |
| --- | --- |
| `Dominant Cycle Length` | 종목/타임프레임의 지배 사이클에 맞춰 밴드 민감도를 바꿀 때 (책의 사이클 도출 방법 참고) |
| `Narrow / Wide Band Width Threshold` | 수축/확장 배경이 켜지는 밴드폭 기준을 바꿀 때 |
| `Show Band Width Background` | 배경 강조를 끄고 선만 보고 싶을 때 |
| `밴드 배경 불투명성 (0=투명, 100=진함)` | 배경 진하기를 조절할 때. **0이면 완전 투명(안 보임)**, 100이면 가장 진함. 기본 15(연한 편) |
| `과매도 / 과매수 참고 레벨` | 참고 점선 기준(기본 30 / 70)을 바꿀 때 |
| `밴드 교차 가격 테이블 표시` / `테이블 위치` / `글자 크기` | 교차 가격 테이블을 끄거나(기본 켜짐), 위치(기본 우측 상단)·글자 크기(기본 작게)를 바꿀 때 |
| `테이블 기준봉` | `실시간봉`(기본 — 현재 형성 중 봉 기준, 틱마다 갱신·리얼타임 리페인팅) / `완성봉`(가장 최근 완성봉 기준, 고정·리페인팅 없음) |

## 주의사항

- `Dominant Cycle Length`는 임의값이 아니라, 원서(4장)에서 설명한 방식대로 **실제 지배 사이클을 도출해 넣어야** 의도대로 동작합니다.
- 초기 `cyclicmemory`봉 구간에서는 밴드와 배경이 안정화되지 않습니다.
- 단독 진입 근거보다, 자리·거래량·추세 지표와 함께 보는 보조 확인용에 가깝습니다.
- `vibration`, `leveling`은 현재 입력값이 아니라 코드 상수입니다. 바꾸려면 소스를 직접 수정해야 합니다.
