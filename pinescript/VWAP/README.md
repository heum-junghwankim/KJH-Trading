# Auto VWAP

트레이딩뷰용 Pine Script 오버레이 지표 설명서입니다.

대상 스크립트:
- [`auto-vwap.pine`](./auto-vwap.pine)

이 지표는 VWAP 누적을 **`최근 N봉 롤링(Recent Bars)` 단일 방식**으로 계산합니다(CEO 지시 — 앵커모드 제거). 이전에는 `현재 세션 기준 VWAP`·`최근 N거래일 기준 VWAP`·`최근 N봉 기준 VWAP`를 앵커모드로 바꿔 볼 수 있었으나, 알고리즘 수학자가 지적한 DRIFT(원본 이치모쿠의 `vwap상태(20)`는 앵커 무관 Recent Bars 고정이 정답) 해소를 위해 **앵커모드 입력·세션/거래일 분기·세션 리셋 로직을 전부 삭제**하고, 전 VWAP(화면 20봉·`vwap상태(20)`·`vwapValue`·지지저항 등)이 Recent Bars 단일로 계산되게 했습니다(참고: 중기추세는 CEO 명세로 `vwapValue`가 아닌 화면 주황 50선 `vwma50` 기준으로 판정하도록 수정됐습니다 — 아래 상태 테이블 항 참조). 핵심은 `평균 체결 단가가 어디인지`, 그리고 `현재 가격이 그 기준에서 얼마나 멀리 벗어났는지`를 빠르게 읽는 데 있습니다.

## 현재 소스 기준으로 보이는 것

| 요소 | 현재 표시 방식 |
| --- | --- |
| VWAP | 선택한 기준 구간의 거래량 가중 평균 단가입니다. |
| Band #1 | VWAP 대비 1차 확장 구간입니다. |
| Band #2 | VWAP 대비 2차 확장 구간으로, 과확장 감시에 더 가까운 선입니다. |
| 밴드 2세트 페인팅(Band #2 4선) | CEO 지시로 차트에 그리는 밴드선은 **Band #2 Upper/Lower만, 2세트(총 4선)**입니다. **세트 A** = `Recent Bars`(기본 **20**) 기준 Upper/Lower #2 → **점선(dotted)**, 색 `bandSetAColor`(기본 흰색 `#FFFFFF`, `Enable Dynamic Line Color` 적용 대상). **세트 B** = `세트 B 기간`(기본 **50**) 기준 Upper/Lower #2 → **대시(dashed)**, 색 `bandSetBColor`(기본 회색 `#B2B5BE`, 동적 이탈색 미적용). 두 세트 모두 같은 `Source`·`Bands Calculation Mode`·`Bands Multiplier #2`를 쓰고 `computeVwapSet`을 두 번 호출해 계산합니다(함수-로컬 `var`라 호출부마다 독립 누적, 확정봉 기준 → 리페인팅 없음). Band #1 선과 VWAP 중앙선은 그리지 않습니다(Band #1 plot `display.none` 고정, VWAP 중앙선은 `VWAP 중앙선 표시` 기본 OFF — 옵트인). **표시 게이트** = `showBand_2`(Band #2 마스터) AND 세트 토글(`세트 A 표시`/`세트 B` 체크) AND 선별 토글(`세트 A/B Upper #2`·`Lower #2`) — 선 표시만 제어하며 값·상태 테이블·Sonar `밴드 내부` fill(세트 A 기준)은 불변입니다. **Recent Bars 정리**: 세트 A 기간은 별도 input을 만들지 않고 기존 `Recent Bars`(기본 20)와 **단일화** — VWAP 중앙선·밴드1·지지/저항 판정·밴드 %라벨·Sonar `밴드 내부` fill·상태 테이블 `밴드 상단(N)/하단(N)`이 모두 이 값을 따릅니다. 세트 B는 **표시 전용**(테이블·판정 미사용). %R·Sonar·기울기/교차 전환가는 `Recent Bars`와 무관(각자 `%R` 기간·Sonar n/k/m·리본 길이)하여 영향이 없습니다. |
| 밴드 계산 타입 | `Log Standard Deviation`, `Absolute Standard Deviation` 중 선택합니다. |
| 누적 방식(고정) | **최근 N봉 롤링(Recent Bars) 단일 방식**입니다(CEO 지시 — 앵커모드 제거). 세션/거래일 앵커 분기·세션 리셋 로직은 삭제됐고, VWAP는 항상 최근 `N`봉 누적 구간을 하나의 이동 창처럼 계산합니다. 세션 경계를 무시하고 현재 타임프레임의 봉 수 기준으로 바로 계산합니다. |
| VWAP 세트 | VWAP·밴드·밴드2는 **단일 화면 세트**로 계산합니다 — window 길이 `Recent Bars = 20`(기본), 소스 `Source`(기본 `hlc3`), 화면 plot·밴드·라벨의 기준입니다. VWAP 계산 헬퍼(`computeVwapSet`)가 window 길이(롤링 길이)와 소스를 인자로 받아 **Recent Bars 롤링(앵커 = `barsLen`봉 전 누적)** 으로 확정봉 기준 누적하므로 리페인팅이 없습니다. |
| 선 굵기·가격축 | VWAP 중앙선은 **1px·점선(dashed)**입니다(CEO 지시: `linewidth=1`·`linestyle=plot.linestyle_dashed` — 밴드2선은 이후 CEO 지시로 도트 `dotted`로 변경, 중앙선은 dashed 유지). ⚠️ **선 색은 CEO 지시로 고정 단색(중립 흰색 `DEFAULT_LINE_COLOR`)** 입니다 — 직전엔 지지/저항 판정에 따라 봉 단위 녹/빨강/흰으로 동적 변색했으나, CEO 지시로 **변색을 제거하고 고정 흰색**으로 전환했습니다(`plot`의 `color` 인자만 `vwapLineColor` → `DEFAULT_LINE_COLOR`로 교체). 색 구성은 VWAP 값을 두 plot으로 나눠, **고정 흰색 선**과 흰색 고정 가격축 라벨을 분리하는 구조입니다(선은 pane에 1회만 그려져 중복선 없음). **VWAP 중앙선의 가격축 라벨은 항상 흰색으로 고정**되도록 별도 plot(제목 `VWAP 가격축 라벨`)으로 흰색만 담당하며, `VWAP 중앙선 표시` 토글과 무관합니다(라벨 plot의 `display`는 불변). ⚠️ **기본 표시 상태는 아래 "기본 표시 옵션" 행 참조** — VWAP 중앙선(본선)은 CEO 지시로 `VWAP 중앙선 표시` 입력 토글(기본 **OFF** — 보기 탭 기본 언체크)로 표시하며, 산식·값은 불변이고 렌더 스타일(1px·점선)·표시 게이트·선 색(고정 흰색)만 변경했습니다. |
| 기본 표시 옵션(Style 탭 기본 체크) | 차트에 지표를 처음 얹었을 때의 **기본 표시 상태**입니다(사용자가 Style 탭·설정에서 각자 켜고 끌 수 있음, 값·조건·색·산식은 전부 불변 — plot의 `display` 인자만 설정). **VWAP 중앙선(본선)**은 CEO 지시로 `VWAP 중앙선 표시` 입력 토글(VWAP Settings 그룹, 기본 **OFF** — CEO 지시로 구 기본 ON에서 변경)로 표시합니다 — 밴드2(`showBand_2`)와 동일 패턴(`displayVwapLine = showVwapLine ? display.all − display.price_scale : display.none`)이라 기본값에서 `display.none`이 되어 **설정 보기(Style) 탭에서 기본 언체크**이며, 사용자가 이 토글(또는 보기 탭)로 켤 수 있습니다. **기본 OFF(`display.none`)**: **VWAP 가격축 라벨**·**Upper Band #1**·**Lower Band #1**(CEO 지시, 불변). Band #1은 plot의 `display`를 `display.none`으로 직접 고정했으며, `showBand_1` 입력 토글과 밴드1 %갭 라벨(`showBand_1` 조건) 로직은 불변입니다. Band #2·리본·이격도 등 다른 plot의 기본 표시는 변경하지 않았습니다. |
| VWAP 선 지지/저항 색 판정(내부 상태 — 선 색 미반영) | ⚠️ **CEO 지시로 VWAP 중앙선 색은 고정 단색(중립 흰색)으로 전환**되어, 아래 지지/저항 색 판정은 **더 이상 VWAP 선 색에 반영되지 않습니다**. `VWAP 선 지지/저항 색 판정` 옵션(기본 **ON**)과 판정 블록(`vwapResistance`/`vwapSupport`/`vwapSRColor`)은 **향후 다른 표시에 재사용하기 위한 내부 상태 판정으로 보존**만 하며, 선 색·차트 표시에는 영향이 없습니다(변색 제거 = 이 색 판정이 선에 안 그려짐). 아래는 보존된 판정 규칙 서술입니다(참고). **"near 구간"** = VWAP와 밴드1 사이의 **동적 %(pct) 범위**입니다(밴드1 전체가 아님). 하단 near `[lowerNear, vwap]`, 상단 near `[vwap, upperNear]`. **`upperNear = vwap + pct×(upperBand1 − vwap)`**, **`lowerNear = vwap − pct×(vwap − lowerBand1)`** — 저항(하단)·지지(상단) **동일 pct 대칭**. **`pct`(구간 비율)는 밴드폭 반비례 동적**입니다: 밴드폭이 **좁을 때(저변동성) 최대 0.60(60%)**, **넓을 때(고변동성) 최소 0.20(20%)**로 수렴합니다. 산식은 `bandWidth1 = upperBand1 − lowerBand1`, `r = bandWidth1 / vwap`(가격 대비 밴드폭 비율, 종목·가격 무관), `t = clamp((r − rLow)/(rHigh − rLow), 0, 1)`, `nearPct = maxPct − t×(maxPct − minPct)`, `pct = clamp(nearPct, 0, 100)/100`입니다 — `r ≤ rLow`(저변동성·좁은밴드)면 `maxPct`(넓은 near), `r ≥ rHigh`(고변동성·넓은밴드)면 `minPct`(좁은 near), 사이는 선형보간(반비례). 기본값은 `VWAP 근처 구간 최소 %(넓을 때)=20`·`최대 %(좁을 때)=60`·`저변동성 임계=0.5%`·`고변동성 임계=2.0%`입니다(임계 뒤집힘·`vwap==0`이면 `t=0` → 최대% 폴백). 색 규약: **지지=녹 / 저항=빨강 / 중립=흰**. 규칙은 다음과 같습니다 — **저항=빨강**(`UPPER_BREAK_LINE_COLOR`) = **① `lowerNear ≤ close ≤ vwap`**(하단 near 안에 종가 마감 = VWAP이 저항) **OR ② `close < lowerNear` AND `high > lowerNear`**(종가는 하단 near 아래로 이탈했지만 **고가**가 하단 near 최저 위 = 꼬리 걸침 되밀림); **지지=녹**(`LOWER_BREAK_LINE_COLOR`) = **③ `vwap ≤ close ≤ upperNear`**(상단 near 안에 종가 마감 = VWAP이 지지) **OR ④ `close > upperNear` AND `low < upperNear`**(종가는 상단 near 위로 이탈했지만 **저가**가 상단 near 최고 아래 = 꼬리 걸침 되밀림); **그 외**(완전 이탈: `close`가 near 구간 밖이고 꼬리도 near에 안 걸침 / 워밍업 `na`) → **중립=흰**(`DEFAULT_LINE_COLOR`). **`close == vwap` 경계**: ①은 `close ≤ vwap`, ③은 `close ≥ vwap`이라 `close == vwap`이 양쪽에 걸립니다 — **저항을 먼저 평가**(코드에서 `if 저항 → else if 지지`)해 `close == vwap`이면 **저항=빨강**으로 확정합니다(부동소수라 실제 동일값은 드묾). **상호배타·미정의 구멍 없음**: ②(`close<lowerNear`)와 ①(`close≥lowerNear`) 배타, ④(`close>upperNear`)와 ③(`close≤upperNear`) 배타, 저항 계열(`close≤vwap` or `close<lowerNear`)과 지지 계열(`close≥vwap` or `close>upperNear`)은 `close==vwap` 외엔 배타이며 `close==vwap`은 위 우선순위로 저항 단일 확정 → 전 조합이 정확히 한 색으로 결정됩니다. **②④의 의미**: ②는 "종가가 하단 near 아래로 이탈했지만 아래꼬리가 아니라 **위꼬리(고가)가 하단 near에 걸쳐 되밀린** 봉"을 저항으로, ④는 "종가가 상단 near 위로 이탈했지만 **저가가 상단 near에 걸쳐 되밀린** 봉"을 지지로 인정합니다(순수 종가 이탈이라도 꼬리가 near를 관통했으면 지지/저항 신호로 봄). **엣지케이스**: 밴드1 편차 0(완전 도지)이면 `bandWidth1=0` → `r=0(≤rLow)`이라 pct=최대나 `upperNear=lowerNear=vwap`로 near 구간이 소멸 — 종가가 그 값이면 ① 해당(저항), 아니면 꼬리(high/low)로 ②④ 판정. 이 색은 봉 단위 series color라 **과거 봉은 값이 확정돼 리페인팅이 없고**, 형성 중 현재봉만 종가/고저 확정 전 색이 바뀔 수 있다가 봉 마감 시 확정됩니다(과거 변조 아님). 판정에 쓰는 `close`·`high`·`low`·`vwap`·밴드1·near는 모두 확정봉 세트값입니다. ⚠️ **선 색 미반영(재확인)**: 위 판정은 내부 상태(`vwapResistance`/`vwapSupport`)와 `vwapSRColor`(색 산출)까지만 계산하고 **VWAP 중앙선 plot에는 그리지 않습니다** — 선 색은 CEO 지시로 고정 흰색(`DEFAULT_LINE_COLOR`)입니다. |
| 선 색상 변화(밴드2 이탈) | `Enable Dynamic Line Color`를 켜면 `Band #2` **이탈 시** 하단 아래 녹색·상단 위 빨간색으로 읽습니다(기본 흰색, `activeLineColor`). 이 옵션은 `Band #1`·`Band #2` 선 색(`activeLineColor`)에 적용됩니다. ⚠️ **VWAP 중앙선에는 미적용**: CEO 지시로 VWAP 선 색이 고정 흰색으로 전환되어, 이 옵션도 VWAP 중앙선 색에는 영향을 주지 않습니다(밴드1·밴드2 선에만 적용). |

## 트레이딩 의미 핵심 4가지

### 1. 가격이 VWAP 위 / 아래에 있는 의미

가격이 VWAP 위에 있으면 `선택한 기준 구간 평균 단가보다 위에서 거래 중`, 아래에 있으면 `평균 단가보다 아래에서 거래 중`이라고 읽습니다.

- 방향 예측선이라기보다 현재 가격의 `비용대 기준 위치`를 보는 도구입니다.
- 실전에서는 `회복 후 유지`, `이탈 후 재진입 실패` 쪽이 더 중요합니다.

요약하면, VWAP은 `평균 단가 기준선`입니다.

### 2. VWAP 근처 왕복 의미

VWAP 근처를 계속 왕복하면 `방향성 추세`보다 `평균 단가 공방`이 진행 중일 가능성이 큽니다.

- 이 구간에서는 추격 진입보다 방향 확정 대기가 더 낫습니다.
- 다른 지표가 좋아 보여도 VWAP 공방이 길면 후속이 약할 수 있습니다.

요약하면, VWAP 공방은 `판단 유보 구간`으로 보는 편이 안전합니다.

### 3. Band #1 접근 의미

Band #1 접근은 `정상 확장` 또는 `첫 과열 구간`에 더 가깝습니다.

- 추세가 막 붙기 시작하는 구간에서도 자주 나옵니다.
- 따라서 Band #1 자체를 반전 신호로 보기보다 `확장 확인`으로 읽는 편이 좋습니다.

요약하면, Band #1은 `추세 확장 확인선`에 가깝습니다.

### 4. Band #2 접근 의미

Band #2 접근이나 이탈은 `강한 확장`, `과열 / 과매도`, `과확장 감시` 의미가 더 큽니다.

- 강한 추세에서는 바깥 체류가 이어질 수 있습니다.
- 그래서 Band #2는 바로 역방향 진입보다 `속도 조절`, `관리`, `후속 확인` 쪽에 더 유리합니다.

요약하면, Band #2는 `공격`보다 `과확장 감시`의 의미가 강합니다.

## 내부 로직

### 1. 기준 구간 — Recent Bars 롤링 단일 고정

VWAP 누적 방식은 **최근 N봉 롤링(Recent Bars) 하나로 고정**되어 있습니다(CEO 지시 — 앵커모드 제거). 과거의 `Session`/`Recent Trading Days` 앵커 분기와 세션 리셋(`ta.change(time("D"))` 류)·세션 누적 배열은 **완전히 삭제**됐습니다. 알고리즘 수학자가 지적한 DRIFT(원본 이치모쿠의 `vwap상태(20)`는 앵커 무관 Recent Bars 고정이 정답)를 해소하려는 조치이며, 화면 20봉·`vwap상태(20)`·`vwapValue`·지지저항 등 **전 VWAP이 Recent Bars 단일로 계산**됩니다(중기추세는 CEO 명세로 `vwapValue` 대신 화면 주황 50선 `vwma50`으로 판정하도록 수정됨).

`Recent Bars`
- 최근 `N`봉(`Recent Bars`, 기본 20)을 하나의 이동 창처럼 계산합니다(앵커 = `N`봉 전 누적값).
- 세션 경계를 무시하고 차트에 보이는 현재 타임프레임 기준 봉 수로 바로 계산합니다.
- 워밍업(봉 수 < `N`)에는 창이 전체 누적으로 자연 폴백됩니다.

### 2. VWAP 계산

현재 코드는 아래 값을 누적해서 씁니다.

- `src * volume`
- `volume`
- `src^2 * volume`

이 누적값으로:
- `VWAP`
- 거래량 가중 분산
- 표준편차 기반 밴드

를 계산합니다.

`computeVwapSet(barsLen, srcArg)` 헬퍼가 window 길이(Recent Bars 롤링 length)와 **소스**를 파라미터로 받아 화면 세트(`length=20`, `src`)를 계산합니다. 누적값(`cumulative*`)은 **함수-로컬 `var`로 내부화**했습니다 — Pine v6에서 함수 내부 `var`는 호출부마다 독립 상태를 가지므로 확정봉 기준으로 누적하며 리페인팅이 없습니다. window = 현재 누적 − `barsLen`봉 전 누적(`cumulative*[barsLen]`)이라 항상 최근 `barsLen`봉 롤링입니다(앵커모드 제거로 세션/거래일 분기·세션 앵커 배열은 삭제됨). 밴드·밴드2도 이 세트의 window에서 산출됩니다. 산식(rolling VWAP + 로그/절대 표준편차 밴드)은 앵커모드 제거 전의 Recent Bars 경로와 동일합니다.

### 3. 밴드 계산 방식

`Bands Calculation Mode`는 두 가지입니다.

`Log Standard Deviation`
- 현재 기본값입니다.
- 거래량 가중 `log(price)` 표준편차를 사용합니다.
- 밴드는 `VWAP * exp(± sigma_log * multiplier)` 형태로 계산되어, 절대 가격보다 비율 변화에 더 민감합니다.
- 가격이 0 이하인 자산에는 적합하지 않습니다.

`Absolute Standard Deviation`
- 거래량 가중 표준편차를 절대 가격 단위로 계산해 밴드 폭으로 사용합니다.

즉 이 지표는 `VWAP 기준선 + 확장 폭 방식`을 바꿔가며 읽는 구조입니다.

> **상태 테이블(재도입):** 이전에는 상태 테이블을 두지 않았으나, SUPER-ICHIMOKU 테이블을 이식해 **우측 상단 상태 테이블을 재도입**했습니다(`상태 테이블 표시` 옵션, 기본 ON — 위 "상태 테이블" 행 참조). 5개 섹션(위→아래: 추세 확인 / 기울기 전환가 / 교차 전환가 / 변동성 임계가 / 지지·저항 임계가 — CEO 지시로 구 `추세 전환가`를 2섹션으로 분할, CEO 지시로 헤더 개명·후행 헤더 신설 후 "후행 추세 확인"→"추세 확인" 개명·최상단 이동)으로, 판정식은 이치모쿠 원본 로직 그대로입니다(캔들 상태·캔들 손절라인 행은 미이식). ⚠️ **`비정상 매수/매도` 테이블 행은 CEO 지시로 삭제**됐습니다 — 비정상은 이미 **캔들 몸통색(`barcolor`)**으로 표현되므로 셀 행만 제거했고, 판정 래치(`abnCandleState`/`abnWatch`)·캔들색은 불변입니다(반등 감시 `abnWatch`는 계산·래치는 유지되나 테이블 표기는 이 행 삭제로 제거). **이격도**는 래치 리셋 판정에 더해 테이블 `이격도 (20)` 셀로 표기합니다.

### 4. 비정상 매수/매도(과매수/과매도) — 이치모쿠 이식

SUPER-ICHIMOKU 메인 지표(`advanced-ichimoku.pine`)의 **"비정상 캔들"** 판정을 그대로 이식했습니다. 목적은 **평균 회귀가 필요한 극단 구간(과매수/과매도)** 을 **캔들 몸통색(`barcolor`)** 으로 한눈에 드러내는 것입니다(과거 배경 `bgcolor`에서 CEO 지시로 전환 — 위 "비정상 매수/매도 캔들색" 참조).

- **cRSI(도미넌트 사이클 RSI)**: 사이클 길이 = `비정상 기준 길이 ÷ 2`(기본 20÷2=10)의 RSI를 Vibration(기본 10)으로 위상 보정·평활한 값. `≥ 절대 과매수(70)`면 과매수, `≤ 절대 과매도(30)`면 과매도.
- **볼린저 밴드 이탈**: `SMA(close, 비정상 기준 길이) ± stdev × 배수(2.0)`. **볼린저 길이는 비정상 전체 기준 길이(`비정상 기준 길이(볼린저 등)`, 기본 20)** 와 동일합니다(CEO 지시로 단일화 — cRSI·ATR·RSI·추적 lookback도 모두 이 값에 연동). 종가가 아닌 **고가/저가**로 판정합니다(종가 실시간 변동이 커서). 상단 초과폭(또는 하단 이탈폭) ÷ 캔들 범위가 `비정상 밴드 초과 비율(0.3)` 이상이면 이탈로 인정.
- **비정상 판정(AND)**: 비정상 매수(=과매수) = cRSI 과매수 **AND** 고가 상단 이탈, 비정상 매도(=과매도) = cRSI 과매도 **AND** 저가 하단 이탈.
- **상태 래치·리셋**: 비정상 봉이 나오면 그 방향 상태를 래치해 다음 비정상 봉까지 유지하고, **이격도(Disparity)가 중립으로 복귀하면 리셋**합니다. 이격도 = `종가 ÷ 이평(기본 SMA 20) × 100`으로, 고정 임계(±10%)와 적응형(자기 표준편차 σ×1.5) 두 기준의 충족 개수로 되돌림을 판정하며, **둘 다 미충족(중립)이면 리셋 트리거**입니다.
- **반등 감시(abnWatch) — 이치모쿠 반등 감시 이식(CEO 지시)**: 비정상 캔들(극단) 발생 뒤 **그 방향과 반대되는 되돌림(반등)** 이 유의미하면 **`abnWatch` 상태**(`+2`=롱 감시, `−2`=숏 감시, `0`=없음)로 래치합니다. 판정 = 비정상 캔들이 뜬 봉의 극단가(롱=`low`·숏=`high`)·RSI·ATR을 기준점(`Ref*`)으로 스냅샷한 뒤, **`abnLookback`(=`비정상 기준 길이`) 봉 이내**에서 ① 반대방향 가격 되돌림(`priceMove`, 롱=`RefPrice−low`·숏=`high−RefPrice`) ≥ `RefAtr × 비정상 반등 감시 ATR 배수`(기본 **1.5**) **AND** ② RSI 되돌림 폭(`rsiMove`) ≤ `비정상 RSI 이동 제한`(기본 **15**)이면 감시 ON. RSI·ATR은 이치모쿠 원본과 동일 길이(`ta.rsi(close, abnLen)`·`ta.atr(abnLen)`, `abnLen=비정상 기준 길이`)이며, 이치모쿠의 **기본/강화 2단 감시는 단일 감시로 통합**된 최신본을 이식했습니다. 리셋은 비정상 상태와 함께 **이격도 중립 복귀 시** `abnWatch`도 `0`으로 돌립니다. ⚠️ **리페인팅 방지(CEO 명시)**: 이치모쿠 원본은 실시간 '빠른 캐치'를 위해 확정봉 가드를 의도적으로 안 걸었으나, 본 이식은 CEO 지시대로 **기준점·감시 래치·리셋을 모두 확정봉(`barstate.isconfirmed`)에서만 갱신**합니다(형성 중 현재봉이 래치를 흔들지 않음 → 신규 리페인팅 없음). 이 실시간성 차이는 CEO 보고 대상입니다. ⚠️ **화면 표시 보류(CEO 판단 대기)**: auto-vwap엔 상태 테이블/셀이 없어(아래 "상태판 없음") 이치모쿠처럼 셀 텍스트("롱 감시"/"숏 감시")로 표기할 자리가 없습니다. 억지로 새 UI를 만들지 않고 **로직만 이식(abnWatch 계산·래치까지)** 했으며, 표시 방식(마커/라벨/셀 등) 확정은 CEO 판단을 기다립니다. `abnWatch` 상태는 이미 계산·래치되어 있어 표시 방식 확정 시 즉시 연결 가능합니다. `비정상 반등 감시 ATR 배수`·`비정상 RSI 이동 제한`은 전략성 파라미터(수학자 리뷰 대상)입니다.

⚠️ **자기완결 이식 근거**: 원본은 기준 길이를 이치모쿠 베이스 라인(`basePeriods`)에, 리셋을 이치모쿠 이격도 블록에 의존했습니다. auto-vwap엔 그 둘이 없으므로 (1) 기준 길이를 **단일 input(`비정상 기준 길이(볼린저 등)`, 기본 20)** 하나로 통일하고(CEO 지시 — 볼린저 + cRSI·ATR·RSI·추적 lookback이 모두 이 값에 연동. 구 별도 `비정상 기준 길이(베이스 라인 대응)` 기본 22는 삭제·통합해 전 기준 길이 22→20으로 통일), (2) 이격도를 **원본 산식·input 그대로 이식**해 자기완결화했습니다. 소스가 같은 기본값이면 원본과 동일한 값을 재현합니다. 반등 감시(`abnWatch`)도 원본 산식(기준점·되돌림 게이트·부호 체계 ±2)을 그대로 이식했고, 두 신설 input(`비정상 반등 감시 ATR 배수`·`비정상 RSI 이동 제한`)은 **title을 이치모쿠와 일치**시키되 auto-vwap의 UI 일관성을 위해 기존 `비정상 매수/매도` 그룹에 배치했습니다(원본 그룹명은 `비정상 캔들`). 매매 신호가 아니라 **표시 전용 국면 표식**이며, 임계·기간은 전략성 파라미터라 임의 변경 시 수학자 리뷰 대상입니다.

## 지수 추세 리본(EMA/DEMA/TEMA) + 정배열/역배열 판정

CEO 설계로 추가한 **지수형 추세 리본**과 그 리본으로 판정하는 **정배열/역배열 상태**(기울기 전환가 `정배열 전환`·`역배열 전환` 행 셀색용)입니다. 차트 배경 페인팅은 [Sonar 모멘텀 배경](#sonar-모멘텀-배경) 절로 옮겨졌습니다. 매매 신호가 아니라 **표시 전용 국면 표식**이며, 기존 auto-vwap 기능(VWAP·밴드·비정상)은 전부 불변입니다.

### 1. 리본 3선(EMA/DEMA/TEMA)

- **계산(리본 소스 기준, 화면 표시 대상).** 선택한 리본 소스에 EMA를 3중 누적합니다: `e1 = EMA(리본 소스, 지수 리본 길이)`, `e2 = EMA(e1, 지수 리본 길이)`, `e3 = EMA(e2, 지수 리본 길이)`. 여기서 **`EMA = e1`, `DEMA = 2·e1 − e2`, `TEMA = 3·e1 − 3·e2 + e3`**를 파생합니다. `지수 리본 길이` 기본 **20**. `리본 소스` 옵션은 **`종가`(=`close`, 기본) / `고저종/3`(=`hlc3`) / `시고저종/4`(=`ohlc4`)**이며, 소스는 **1차 EMA(`e1`)에만** 적용되고 `e2`/`e3`(및 DEMA/TEMA·로그 slope·기울기 3행·정배열/역배열 판정)는 `e1`의 EMA/파생이라 소스 변경이 **자동 전파**됩니다. 기본 `종가`는 기존 `close` 고정과 **완전 동일**합니다(회귀 0). **화면에 그려지는 것은 이 리본 3선뿐**입니다.
- **의미.** DEMA는 EMA의, TEMA는 DEMA의 지연을 각각 줄인 지수형 추세선입니다. 상승 추세가 붙으면 **TEMA > DEMA > EMA(정배열)**, 하락 추세면 역배열로 벌어지며, 세 선의 상대 위치·기울기가 추세 국면을 압축해 보여줍니다.
- **표시.** 각 선 **1px**, 색은 옵션(`EMA 선 색`=노랑 / `DEMA 선 색`=하늘색 / `TEMA 선 색`=분홍). **우측 가격축 라벨 ON**(CEO 지시로 `display.all` — 차트 선 + 우측 가격축에 세 선(EMA/DEMA/TEMA)의 현재값 라벨 표시). **라벨 색은 각 선 색을 그대로 따릅니다**(plot의 `color`가 가격축 라벨 색에 자동 반영 — EMA=노랑·DEMA=하늘색·TEMA=분홍). `지수 추세 리본 표시(EMA/DEMA/TEMA)` 토글(기본 **ON**, 끄면 선·라벨 함께 숨김). 소스는 `리본 소스`(기본 `종가`) 옵션으로 고릅니다. ⚠️ 선 굵기·색·값·리페인팅·기울기 3행·배경 판정은 **불변**이며, `price_scale` 라벨 노출만 추가했습니다(가격축 라벨 3개 증가).
- **리페인팅 없음.** `ta.ema` 누적(확정 성격)이라 과거봉 값이 확정되어 신규 리페인팅이 없습니다.

### 2. 로그 기울기 3행 + 배열 상태 bgFillState (1봉 기울기 지표간 서열 — CEO 재정의)

> ⚠️ **[2026-10-16 현행] 기울기 3행·`기울기 배열` 행의 테이블 표시는 CEO 지시로 제거**됐습니다(섹션이 `추세 전환가` 4행으로 교체 — 아래 "3. 기울기 전환가 · 교차 전환가" 절 — 이후 CEO 지시로 `추세 전환가` 섹션은 2섹션으로 분할). 이 절의 로그 slope 계산(ㄱ/ㄴ/ㄷ)·셀색 판정 bool·`bgFillState`는 **내부 계산으로 그대로 존치**되며, `bgFillState`는 이제 `정배열 전환`·`역배열 전환` 행의 셀 색·표시 규칙에 쓰입니다. 아래 "표시(테이블 3행)"·"셀 색 수준 보정"·"4행 셀색" 서술은 제거 전 표시 기준의 이력입니다.

테이블 상단 3행(EMA/DEMA/TEMA)을 **각 리본선 `ln(line)` 기반 로그 slope 3종**으로 표시하고(각 행 셀 색 = 시간축 ㄱ>ㄴ>ㄷ 서열), **세 이평선의 1봉 로그 기울기(ㄱ) 지표간 서열**(TEMA>DEMA>EMA=녹·EMA>DEMA>TEMA=적)을 판정합니다(CEO 재정의·수학자 검증 산식). ⚠️ **[현행] 이 서열 판정은 이제 밴드2 배경이 아니라 상태 테이블 `정배열 전환`·`역배열 전환` 행(기울기 전환가) 셀색 전용**이며, 밴드2 배경은 **Sonar 모멘텀 기준**으로 칠합니다([Sonar 모멘텀 배경](#sonar-모멘텀-배경) 절·위 표 `Sonar 모멘텀 배경` 참조). 옛 TEMA 로그 행 색 매핑·`baseState`(종가 리본 서열)·전환 셀 컨플루언스·ATR 정규화 모드·전환 임계 역산·전환 후보·억제/래치/플립은 **전면 제거**됐습니다(dangling 0). ⚠️ **[CEO 지시·현행] 이 지표간 서열 판정(`bgFillState`)은 더 이상 밴드 배경을 칠하지 않습니다** — 배경 페인팅은 밴드워킹을 거쳐 현재 **Sonar 모멘텀**(`sonarState`)으로 교체됐고, `bgFillState`는 **기울기 전환가 `정배열 전환`·`역배열 전환` 행 셀색** 전용 내부 상태로 존치합니다(값·산식 100% 불변). ⚠️ 종전의 또 다른 소비처였던 **정렬 삼각형의 `noBg`·래치 해제**는 **삼각형 제거(CEO 지시)로 사라졌고**, 현재 `bgFillState`의 유일한 소비처는 `정배열 전환`·`역배열 전환` 행 셀색(`entArrColor`)·표시 규칙입니다.

**로그 slope 3종(각 행 = 리본선 `line` ∈ {emaLine, demaLine, temaLine}, 모두 `ln(line)` 기준).**

- **na/양수 가드.** `yk = line[k] > 0 ? math.log(line[k]) : na`. 하나라도 `na`면 그 slope `na` → 셀 회색.
- **ㄱ (2점, 봉당 로그수익률).** `slopeA = ln(line[0]) − ln(line[1])`.
- **ㄴ (3점 OLS, `line[0..2]`).** x축 과거→현재 증가(`x=2,1,0` for k=0,1,2). 등간격 최소제곱 분모 `N·Σx²−(Σx)²=6`: `slopeB = (3·(2·y0 + 1·y1 + 0·y2) − 3·(y0+y1+y2)) / 6`.
- **ㄷ (5점 OLS, `line[0..4]`).** `x=4,3,2,1,0` for k=0..4, 분모 50: `slopeC = (5·(4·y0+3·y1+2·y2+1·y3+0·y4) − 10·(y0+y1+y2+y3+y4)) / 50`.
- **부호 정합(검산 완료).** x축을 과거→현재 증가로 두어 **우상향(가속)=양수**. 상승 가속 → ㄱ>ㄴ>ㄷ(모두 양수), 하락 가속 → ㄱ<ㄴ<ㄷ(모두 음수), 순수 선형 상승 → ㄱ=ㄴ=ㄷ(봉당 로그수익률로 일관).

**표시(테이블 3행).** `ㄱ | ㄴ | ㄷ` 순, **%/봉(×100)** 스케일, 부호+**소수2자리**+`%`(예 `+1.00% | +0.70% | +0.50%`), `na`는 `-`, 구분자 `" | "`. **1/3/5 상수 고정**(input 노출 없음). 툴팁에 "%/봉(로그수익률)·봉마감 확정" 명기. ⚠️ **표시(2자리)와 셀 색 판정(2자리 반올림)의 자릿수가 이제 일치**(CEO 지시 — 앞서 "표시 1자리·판정 2자리"였던 것을 표시도 2자리로 되돌림). 표시 헬퍼 `f_slopePctStr`의 포맷 `"0.0"`→`"0.00"` 한 곳만 바꿔 1행(TEMA ㄱ|ㄴ|ㄷ)~4행(기울기 배열) 전 slope 표시가 일괄 2자리가 됩니다.

**셀 색(데드존 없음·2자리 반올림 부등호, CEO 명세).** 각 slope를 **%(×100) 소수2자리 반올림**한 값(`pctR2(s) = math.round(s·10000)/100`)으로 서열 비교합니다(표시 자릿수와 동일). 2자리 반올림 후 두 값이 같아지면 부등호 불성립 → 회색(노이즈 완화).

- **녹색** = `pctR2(slopeA) > pctR2(slopeB) > pctR2(slopeC)`(ㄱ>ㄴ>ㄷ) → `color.new(ltUpColor, 30)`.
- **적색** = `pctR2(slopeA) < pctR2(slopeB) < pctR2(slopeC)` → `color.new(ltDownColor, 30)`.
- **회색** = 하나라도 `na` 또는 그 외 → `color.new(color.gray, 40)`.

**셀 색 수준(level) 보정 — 서열=방향 가속, 채도=수준 부호(CEO 지시).** 서열(부등호) 판정은 그대로 두고, **ㄱ(slopeA)의 부호**로 채도만 낮춥니다(투명도는 3행 톤 `30` 유지, T/D 크로스·이격도 행의 4-상태 색 체계와 톤 통일). 부호는 **표시값과 어긋나지 않도록 `pctR2`(2자리 반올림) 기준**으로 판정하므로, 화면에 `+0.00%`로 보이는 값이 색에서만 음수로 취급되는 불일치가 없습니다(반올림 후 `0.00`은 음수도 양수도 아니므로 **원색 유지**).

**ㄱ 단독 판정의 동일성 증명(수학자 검토·CEO 결재).** 녹 조건이 `pctR2(ㄱ) > pctR2(ㄴ) > pctR2(ㄷ)`이므로 **녹 분기에서 ㄱ은 세 값의 최대**입니다 → `pctR2(ㄱ)<0`이면 ㄴ·ㄷ도 자동으로 음수. 따라서 CEO 지시 원문의 "**ㄱ·ㄴ 둘 다 음수**"와 `pctR2(ㄱ)<0` **단독은 논리적으로 완전히 동일한 조건**이며, 코드는 중복을 제거한 단독 판정(`negA`)을 씁니다(**결과 색 100% 불변**). 적 분기도 대칭 — 적 조건상 ㄱ이 최소이므로 `pctR2(ㄱ)>0` ⟹ ㄴ·ㄷ도 양수(`posA`). ⚠️ **향후 서열 규칙(`f_logGreen`/`f_logRed`)을 바꾸면 이 동일성이 깨지므로** 보정 조건도 반드시 함께 재검토해야 합니다(의미가 조용히 갈라지는 것을 막기 위한 기록).

| 서열 | ㄱ 부호(`pctR2` 기준, 괄호 = 동일 조건인 CEO 원문) | 결과 색 | 트레이딩 의미 |
| --- | --- | --- | --- |
| 녹색(ㄱ>ㄴ>ㄷ) | ㄱ<0 (= ㄱ·ㄴ 모두 음수) | 저채도 녹 `color.new(SR50_ABOVE, 30)` | 아직 **하락권**에서의 감속(반등 초기 후보) — 상승 가속과 구분 |
| 녹색(ㄱ>ㄴ>ㄷ) | 그 외(ㄱ이 양수/0) (= ㄱ 또는 ㄴ이 양수/0) | 원색 녹 `color.new(ltUpColor, 30)` | 상승권 상승 가속(온전한 강세) |
| 적색(ㄱ<ㄴ<ㄷ) | ㄱ>0 (= ㄱ·ㄴ 모두 양수) | 저채도 적 `color.new(SR50_BELOW, 30)` | 아직 **상승권**에서의 감속(고점 둔화 후보) — 하락 가속과 구분 |
| 적색(ㄱ<ㄴ<ㄷ) | 그 외(ㄱ이 음수/0) (= ㄱ 또는 ㄴ이 음수/0) | 원색 적 `color.new(ltDownColor, 30)` | 하락권 하락 가속(온전한 약세) |
| 중립 / `na` | — | 회색 `color.new(color.gray, 40)` | 판정 불가·서열 불성립 |

⚠️ 이 보정은 **1~3행(TEMA/DEMA/EMA 기울기)에만** 적용됩니다. **4행 `기울기 배열`은 대상이 아니며**(셀 색 = 배열 상태 `bgFillState` 일치 유지), 배열 상태 판정(`anyCellRed/Green`→`bgFillState`) 등 `emaLogGreen/Red` 계열 **판정 bool을 쓰는 다른 로직은 전혀 바뀌지 않습니다**(채도만 달라지는 표시 전용 변경).

⚠️ **[현행 반영] 아래 판정은 이제 '배경 페인팅'이 아니라 '기울기 전환가 `정배열 전환`·`역배열 전환` 행 셀색' 전용입니다**(⚠️ 종전에 함께 소비하던 삼각형 `noBg` 판정은 정렬 삼각형 제거로 사라짐)(CEO 지시로 배경은 밴드워킹을 거쳐 현재 Sonar 모멘텀으로 교체). 산식·값·변수명은 **전부 종전 그대로**이며, 달라진 것은 이 결과가 밴드2 배경 fill에 더 이상 연결되지 않는다는 점뿐입니다.

**`bgFillState`(구 밴드 배경 판정) = 1봉 기울기(ㄱ) 지표간 서열(CEO 재정의) + 배경 필터 방식 4모드(CEO 지시·수학자 검증).** 셀 색(각 행 시간축 ㄱ>ㄴ>ㄷ)과 **분리된 별도 기준**으로, 세 이평선의 **ㄱ**(1봉 로그 기울기 = `emaSlA`/`demaSlA`/`temaSlA`)을 지표간 비교합니다(셀 색 판정과 동일하게 `pctR2` 2자리 반올림). 순수 서열은 **정배열 `bgSeqBull` = `pctR2(temaSlA)>pctR2(demaSlA)>pctR2(emaSlA)`(TEMA>DEMA>EMA)**, **역배열 `bgSeqBear` = `pctR2(emaSlA)>pctR2(demaSlA)>pctR2(temaSlA)`(EMA>DEMA>TEMA)**이고, 이를 **`밴드 배경 필터`(4모드, 기본 `정규화 갭`, 옵션 순서 `미적용 → 정규화 갭 → 기울기 크기 게이트 → 상대 데드존`)**로 필터해 최종 `bgBull`/`bgBear`를 산출합니다.

**배경 필터 4모드.** 공통 스케일 **V = ATR(14)/close**(무차원 per-bar 변동성 근사, `close>0` 가드 → `bgVok = not na(bgV) and bgV>0`), 갭 **g1 = temaSlA − demaSlA**·**g2 = demaSlA − emaSlA**(원값, 2자리 반올림 전). `ltAtrTable = ta.atr(14)`은 추세 셀 데드밴드와 공유되며, 이 필터가 배경 판정보다 위에서 쓰므로 **선언 위치를 리본 slope 직후로 상향**(값·중복 호출 불변, 추세 셀 블록은 재정의 없이 재사용)했습니다.

- **`미적용`**: `bgBull = bgSeqBull`·`bgBear = bgSeqBear`(순수 부등호, 필터 없음 — 이전 동작).
- **`정규화 갭`**(기본): `bgBull = bgVok and g1/V≥τ and g2/V≥τ`·`bgBear = bgVok and −g1/V≥τ and −g2/V≥τ`(`τ`=`정규화 갭 임계 τ` 기본 0.10). **V>0 나눗셈 가드 필수**(`bgVok`가 false면 결과 false).
- **`상대 데드존`**: `bgBull = not na(bgV) and g1≥k·V and g2≥k·V`·`bgBear = not na(bgV) and (−g1)≥k·V and (−g2)≥k·V`(`k`=`상대 데드존 배수 k` 기본 0.10). **곱셈이라 V=0 안전**(V=0이면 데드존 폭 0 → 순수 부등호로 회귀), `not na(bgV)`로 close 결측만 차단.
- **`기울기 크기 게이트`**(부호 판정 — CEO 승인 B안·수학자 검산): `bgBull = bgSeqBull and not na(bgV) and temaSlA ≥ +m·V`·`bgBear = bgSeqBear and not na(bgV) and temaSlA ≤ −m·V`(`m`=`기울기 크기 배수 m` 기본 0.10). 종전 `|temaSlA|≥m·V`는 배열 방향과 반대 부호 가지(정배열인데 TEMA ㄱ ≤ −m·V)도 통과시켰으나, 이제 TEMA ㄱ가 **배열 방향으로** m·V 이상이어야 인정합니다. 이 정의에서 `정배열 전환`·`역배열 전환` 행의 게이트 전환가(TEMA 목표 기울기 `e^{±m·V}`를 max/min에 반영)는 판정식과 정확히 일치합니다. **기준 slope = TEMA ㄱ**(`temaSlA`) — 정배열에서 세 slope 중 최대, 역배열에서 최소인 **정렬 방향 대표값**.

전 모드 **`bgHasSlopes`(세 slope not-na) 가드 공통**(`if bgHasSlopes` 블록 밖은 `false` 초기값 유지 → 배경 없음), τ/k/m은 해당 모드에서만 노출됩니다. ⚠️ **파라미터 튜닝 금지**: τ/k/m은 배경 노이즈를 줄이는 **표시 가독성 파라미터**이며 종목별 튜닝·백테스트 최적화 대상이 아닙니다. ⚠️ **셀 색 컨플루언스(AND, CEO 지시)는 전 모드 공통**: 지표간 서열이 성립해도 **기울기 3행(EMA/DEMA/TEMA) 셀 색과 어긋나면 배경 억제(0)** — 녹 배경(`bgBull`)이어도 3행 셀 중 하나라도 적(`anyCellRed = emaLogRed or demaLogRed or temaLogRed`)이면 억제, 적 배경(`bgBear`)이어도 3행 셀 중 하나라도 녹(`anyCellGreen = emaLogGreen or demaLogGreen or temaLogGreen`)이면 억제. 셀 색이 na(회색)면 red/green 둘 다 false라 억제하지 않습니다(정상). 최종: `bgFillState = (bgBull and not anyCellRed) ? 1 : (bgBear and not anyCellGreen) ? -1 : 0`. 셀 색 판정 변수(`emaLogGreen/Red` 등)는 기울기 3행 블록 것을 **그대로 재사용**(셀 색 자체 불변). 기존 배경 색·투명도 input(`정배열 배경색`·`역배열 배경색`·`배경 투명도` 70)·z-order·fill 위치를 **그대로 재사용**(색·매핑 변경 아님, 판정에 컨플루언스만 추가). ⚠️ 배경 = **지표간 서열 AND 3행 셀 색 정합** — 셀 색(시간축)은 불변이고, 배경만 지표간 서열에 셀 색 정합을 AND로 결합.

```pine
// 로그 slope 3종(수학자 검증 산식). 1/3/5 상수 고정.
f_logY(v) => v > 0 ? math.log(v) : na
f_logSlopes3(l0, l1, l2, l3, l4) =>
    y0 = f_logY(l0), y1 = f_logY(l1), y2 = f_logY(l2), y3 = f_logY(l3), y4 = f_logY(l4)
    sA = (na(y0) or na(y1)) ? na : y0 - y1                                   // ㄱ 2점
    sB = (…na…) ? na : (3*(2*y0+1*y1+0*y2) - 3*(y0+y1+y2)) / 6               // ㄴ 3점 OLS
    sC = (…na…) ? na : (5*(4*y0+3*y1+2*y2+1*y3+0*y4) - 10*(y0+y1+y2+y3+y4))/50 // ㄷ 5점 OLS
    [sA, sB, sC]
// 셀 색: green = sA>sB>sC, red = sA<sB<sC (각 행 시간축 ㄱ>ㄴ>ㄷ, na면 둘 다 false=회색, 데드존 없음)
[emaSlA, _eB, _eC]   = f_logSlopes3(emaLine,  emaLine[1],  emaLine[2],  emaLine[3],  emaLine[4])
[demaSlA, _dB, _dC]  = f_logSlopes3(demaLine, demaLine[1], demaLine[2], demaLine[3], demaLine[4])
[temaSlA, _tB, _tC]  = f_logSlopes3(temaLine, temaLine[1], temaLine[2], temaLine[3], temaLine[4])
// 배경: 세 이평선 ㄱ(1봉 기울기)의 지표간 서열(pctR2 2자리 반올림, na 가드) + 필터 4모드(공통 V=ATR/close·g1·g2)
ltAtrTable = ta.atr(14)                        // 추세 셀과 공유. 배경 판정 위로 선언 상향(값·중복 불변)
bgHasSlopes = not na(emaSlA) and not na(demaSlA) and not na(temaSlA)
bgV   = close > 0 ? ltAtrTable / close : na    // 무차원 per-bar 변동성 근사(close>0 가드)
bgVok = not na(bgV) and bgV > 0
bgG1  = (na(temaSlA) or na(demaSlA)) ? na : temaSlA - demaSlA
bgG2  = (na(demaSlA) or na(emaSlA))  ? na : demaSlA - emaSlA
bgSeqBull = bgHasSlopes and f_pctR2(temaSlA) > f_pctR2(demaSlA) and f_pctR2(demaSlA) > f_pctR2(emaSlA)
bgSeqBear = bgHasSlopes and f_pctR2(emaSlA)  > f_pctR2(demaSlA) and f_pctR2(demaSlA) > f_pctR2(temaSlA)
bool bgBull = false
bool bgBear = false
if bgHasSlopes
    if bgFilterMode == "정규화 갭"                                   // V>0 나눗셈 가드
        bgBull := bgVok and (bgG1 / bgV >= bgGapTau) and (bgG2 / bgV >= bgGapTau)
        bgBear := bgVok and (-bgG1 / bgV >= bgGapTau) and (-bgG2 / bgV >= bgGapTau)
    else if bgFilterMode == "상대 데드존"                            // 곱셈이라 V=0 안전(na만 가드)
        bgBull := not na(bgV) and (bgG1 >= bgDeadK * bgV) and (bgG2 >= bgDeadK * bgV)
        bgBear := not na(bgV) and ((-bgG1) >= bgDeadK * bgV) and ((-bgG2) >= bgDeadK * bgV)
    else if bgFilterMode == "기울기 크기 게이트"                     // 순수 서열 AND TEMA ㄱ 부호 판정(배열 방향 m·V)
        bgBull := bgSeqBull and not na(bgV) and (temaSlA >= bgSizeM * bgV)
        bgBear := bgSeqBear and not na(bgV) and (temaSlA <= -bgSizeM * bgV)
    else                                                             // 미적용: 순수 부등호
        bgBull := bgSeqBull
        bgBear := bgSeqBear
// 셀 색 컨플루언스(AND, 전 모드 공통): 배경이 서열이어도 3행 셀 색이 어긋나면 억제(0)
anyCellRed   = emaLogRed or demaLogRed or temaLogRed        // 3행 중 하나라도 적
anyCellGreen = emaLogGreen or demaLogGreen or temaLogGreen  // 3행 중 하나라도 녹
bgFillState = (bgBull and not anyCellRed) ? 1 : (bgBear and not anyCellGreen) ? -1 : 0  // 서열 AND 셀 색 정합
```

- **리페인팅(CEO 명시).** ㄱ이 현재봉 `[0]`을 포함하므로 값·셀색·배경이 라이브 봉 동안 갱신되고 봉 마감 시 확정됩니다. **미래참조 없음**(셀색은 `line[0..4]`, 배경은 `line[0..1]`만). 과거봉은 확정 후 고정.
- **차트 배경과 무관.** 위 `bgFillState`는 차트를 칠하지 않습니다(기울기 전환가 `정배열 전환`·`역배열 전환` 행 전용). 밴드2 영역 배경은 [Sonar 모멘텀 배경](#sonar-모멘텀-배경) 절의 `sonarState`가 칠합니다(구 밴드워킹 `bgWalkPaintState`·`showRibbonExpBg`·`ribbonBgTransp`는 삭제). 밴드2 선(plot) 색은 `activeLineColor`(무조건) 고정, 밴드2 값·산식은 불변.
- **표시 전용.** 매매 판정·밴드와 무관합니다. `지수 리본 길이`(기본 20)만 전략성 파라미터(수학자 리뷰 대상)이며, 배경·셀색 판정 자체엔 별도 임계 입력이 없습니다(로그 slope를 **%(×100) 소수2자리 반올림**한 값의 순서만 비교, 데드존 없음). 표시도 **소수2자리**로 판정과 자릿수가 일치합니다(CEO 지시 — 앞서 표시 1자리였던 것을 2자리로 되돌림).

> **제거된 옛 표시(리본 갭 변화 5행):** 기울기 배열(4행) 아래에 두었던 **`리본 갭 변화` 5행**(인접 이동평균 로그갭의 1봉 변화 = 리본 확장/수축 속도, MACD 히스토그램 원리의 리본 다층 확장)은 **CEO 지시로 전면 제거**됐습니다(테이블 표시 간소화). 관련 로직(`gapT`/`gapD`/`gapE`·`ribbonGapChgT/D/E`·`slopeChgText`·`slopeChgTooltip`)을 모두 삭제하고 그 아래 테이블 row 인덱스를 −1 재정렬(총 행수 19→18)했습니다. `slopeA`(`temaSlA`/`demaSlA`/`emaSlA`)·`f_logY`·`f_slopePctStr`는 기울기 1~4행·리본 계산에 계속 쓰이므로 유지합니다.

### 3. 기울기 전환가 · 교차 전환가 — 추세전환 임계가격(P*) 6행 (CEO 지시 2026-10-16, 구 헤더 `추세 진입` → `추세 전환가` → 2섹션 분할)

> **[현행] 섹션 구성(CEO 지시):** 구 `추세 전환가` 단일 섹션(헤더 1 + 6행)을 성격에 따라 **2섹션**으로 나눴습니다(테이블 행 인덱스만 이동, 2×20→2×21). 이후 CEO 지시로 기울기 섹션 행 순서를 TEMA→DEMA→정배열→역배열로 재배치하고, 교차 섹션 행 이름·값 접두어를 `전환`→`교차`로 바꿨습니다. 값 계산·셀 색·표시 규칙은 전부 불변입니다.

> | 섹션(헤더 행) | 데이터 행(위→아래) | 의미 |
> | --- | --- | --- |
> | **`기울기 전환가`** (row 4) | `TEMA 전환`(5) → `DEMA 전환`(6) → `정배열 전환`(7) → `역배열 전환`(8) | 이평선 1봉 기울기 부호·서열 전환 — TEMA→DEMA 단계적 진입·확인, 배열 정찰 |

> 헤더 툴팁은 섹션별로 분리(`ENTRY_SLOPE_TIP`·`ENTRY_CROSS_TIP`, 각 최대 3문장, 기준봉 모드 분기 유지). 섹션 전용 on/off 토글은 원래 없고, 두 섹션 모두 `상태 테이블 표시` 한 토글로 함께 제어됩니다. 아래 이력 서술의 `추세 전환가`는 현 두 섹션을 합친 6행을 가리킵니다.

구 `선행 추세 확인` 섹션(TEMA/DEMA/EMA 기울기 3행·`기울기 배열`·`T/D 크로스`·`D/E 크로스`, 총 6행)을 **`추세 전환가`(당시 헤더 `추세 진입`) 섹션 4행**으로 교체했습니다(이후 CEO 지시로 `배열 전환` 1행을 `정배열 전환`·`역배열 전환` 2행으로 분리 — 중립 시 한 셀에 두 줄로 보이던 문제 해소 → 이후 CEO 지시로 섹션 첫 행에 `Sonar 전환`(현 `Sonar 교차`) 추가, 현재 6행). 기울기 %나 크로스 %를 보여 주는 대신, **"다음 봉이 몇에 마감하면 추세 조건이 바뀌는가"를 가격(P*)으로** 보여 줍니다. 수식은 알고리즘 수학자 제안서(`auto-vwap 추세전환 예상가격 제안`) §2를 그대로 따릅니다.

> ⚠️ **P*는 조건부 가격이지 예측이 아닙니다.** "다음 봉이 그 가격 이상(이하)으로 마감하면 조건이 충족된다"는 뜻일 뿐, 도달 확률이나 도달 후 기대수익은 말해 주지 않습니다. 엣지는 아직 검증되지 않았습니다(이벤트 스터디 대기). 매매 신호가 아닌 참고용입니다.

**기준봉: `추세 진입 기준봉` 설정(기본 `완성봉`).** cRSI `테이블 기준봉`과 같은 의미·같은 판정식입니다(`상태 테이블` 그룹).
- **`완성봉`(기본)**: 가장 최근 완성봉 기준 — 형성 중이면 직전봉(`entryOff=1`, 제안서 `X[1]`), 마감된 마지막 봉(장 마감·바 리플레이)이면 그 봉(`entryOff=0`). 봉 마감 판정은 cRSI `crK`와 같은 시간 판정 `timenow ≥ time_close`(`time_close`가 na인 틱·레인지 등 가격 기반 차트는 `barstate.isconfirmed` 폴백, isconfirmed도 OR)입니다. 형성 중 봉의 틱 변동에 **값이 고정**되고(리페인팅 없음), 가격은 "형성 중이거나 다음에 올 봉의 종가가 이 값이면 조건이 바뀐다"는 뜻입니다.
- **`실시간봉`**: 현재 형성 중인 봉 `[0]`까지를 고정된 과거로 보고 **다음 봉 종가 C**를 미지수로 역산합니다(`entryOff=0`, 제안서 `X[0]`). 값은 **틱마다 다시 계산**되고(의도된 리얼타임 리페인팅), 봉 마감 시점 값은 완성봉 모드와 같습니다.
- 히스토리 봉에서는 두 모드 모두 `entryOff=0`이라 과거 값은 변하지 않습니다(미래참조·`request.*` 없음). 오프셋 1 참조는 `indicator(max_bars_back=1000)` 버퍼 안입니다.
- **% 기준 = 기준봉 종가 `close[entryOff]`**(cRSI `crClose1 = src[crK]`와 동일): 실시간봉 모드는 현재가, 완성봉 모드(형성 중)는 직전 완성봉 종가. `도달불가` ±50% 판정도 같은 기준입니다.

**수식 개요(제안서 §2).** 3중 EMA 누적이라 다음 봉 선 값은 종가 C에 대해 선형입니다: `L' = a_L·C + b_L`(α=2/(리본 길이+1), β=1−α, e1p/e2p/e3p = 기준봉 누적값).

| 선 | a_L (길이 20) | b_L |
| --- | --- | --- |
| EMA | α = 0.0952 | β·e1p |
| DEMA | 1−β² = 0.1814 | β·[(2−α)·e1p − e2p] |
| TEMA | 1−β³ = 0.2594 | β·[(3−3α+α²)·e1p − (3−α)·e2p + e3p] |

- **Sonar 교차**: Sonar = EMA(종가,n) − EMA(종가,n)[k], Signal = EMA(Sonar,m). αs=2/(n+1), βs=1−αs, E = Sonar의 EMA. 다음 봉 `sonar' = αs·C + βs·E[o] − E[o+k−1]`(다음 봉의 k봉 전 EMA는 기준봉 기준 `E[o+k−1]`로 이미 고정). `0선` 판정은 `sonar' = 0` → `C* = (E[o+k−1] − βs·E[o])/αs`. `Signal 교차` 판정은 `sonar' − signal' = βm·(sonar' − sig[o])`(βm=1−2/(m+1))이므로 `sonar' = sig[o]` → `C* = (sig[o] + E[o+k−1] − βs·E[o])/αs`. m=1이면 βm=0이라 전환 불가 → `-`. Sonar는 종가 고정이라 `소스≠종가` 가드는 적용하지 않습니다.
- **TEMA/DEMA 전환**: `L' = L[0]`(선이 꺾임) → `C* = (L[0] − b_L)/a_L`.
- **T/D 교차**: `TEMA' = DEMA'` → `X = −B/(α·β²)`, `B = β·[β²·e1 − (2−α)·e2 + e3]`(기존 `f_crossX` 그대로).
- **정배열 전환·역배열 전환(근사)**: 갭 `g1 = ㄱT − ㄱD ≥ s` → `K = (T[0]/D[0])·e^s`, `C* = (K·b_D − b_T)/(a_T − K·a_D)`. `g2`(DEMA/EMA)도 같은 형태. **정배열 진입가 = max(C*_g1, C*_g2)**, 역배열은 대칭(`e^{−s}`, min). 문턱 s는 `밴드 배경 필터` 모드를 따릅니다 — `정규화 갭` τ·V, `상대 데드존` k·V, `미적용`·`기울기 크기 게이트` 0(게이트 모드는 TEMA 목표 기울기 `L' = L[0]·e^{±m·V}`를 max/min에 추가). V(ATR14/종가)를 기준봉 값으로 동결하고 셀 색 컨플루언스·2자리 반올림을 생략한 **필요조건**이므로, 봉 마감 후 셀 색으로 최종 확인합니다. 특히 `미적용`·`기울기 크기 게이트` 모드는 셀 색 판정이 기울기를 소수 2자리(%)로 반올림해 비교하므로 **실제 전환가가 표시가보다 더 멀 수 있습니다(리본 길이 20 기준 최대 약 0.15%, 길이에 거의 비례해 커짐 — 예 50이면 약 0.3%)**(셀 툴팁에는 CEO 지시로 "근사값이라 실제 전환가가 표시가보다 조금 멀 수 있으니 봉 마감 후 셀 색으로 확인"으로 요약 표기).

**표시 규칙.**
- 포맷 `{이벤트} : {가격} ({기준봉 종가 대비 %})` — 가격 포맷은 지지·저항 행과 같은 `srLineFmt`(천 단위 쉼표, mintick 자릿수), %는 `f_srPctText`와 같은 포맷(소수 1자리·부호 항상, `-0.0` 방지)의 `f_entPctText`로 기준가를 기준봉 종가로 받습니다. %는 표시된(틱 반올림된) 전환가 기준입니다.
- **틱 반올림**: 상향(상승·골든·정배열) 전환가는 틱 올림(`ceil`), 하향(하락·데드·역배열)은 틱 내림(`floor`) — 표시가에 도달하면 실제로 조건이 성립합니다.
- **`도달불가`**: P*≤0이거나 기준봉 종가 대비 ±50% 초과(표시 반올림 기준 ±50.0% 초과 — 상수 `ENTRY_PCT_CAP = 50.0`, Sonar 교차 포함 기울기·교차 전환가 6행 공통). CEO 지시로 구 ±30%에서 ±50%로 완화했습니다(구 기준은 cRSI 밴드 교차 테이블과 같았으나, cRSI는 이후 도달불가를 폐지해 지금은 기울기·교차 전환가 섹션 전용 기준입니다).
- **`소스≠종가`**: `리본 소스`가 `고저종/3`·`시고저종/4`이면 P*가 종가 하나로 환원되지 않아 계산값을 표시하지 않습니다(제안서 권고).
- `-`: 워밍업·na·분모 퇴화.

**정리 내역.** 기울기 3행 표시(`f_slopePctStr`·`f_logSlope3Text`·`f_logSlope3Color`·`ema/dema/temaAngleText/Color`), `slopeArrText`, D/E 크로스 계산 일체(`dexA`·`f_crossXDE`·`f_crossPctDE`·`dexP0..4`·`dex*` 4-상태·`dexCellColor`·`dexText`), `tdxText`·`f_pctSignedStr`, 구 행 툴팁 6개를 삭제했습니다. **존치**: 로그 slope 계산과 셀색 판정 bool(`emaLogGreen/Red` 등 — `bgFillState` 컨플루언스), `bgFillState`와 필터 input 4개, T/D SSOT(`f_crossX`·`tdxP0..4`·평균·4-상태 bool·`tdxCellColor`), 밴드 배경(당시 밴드워킹 — 이후 Sonar 모멘텀으로 교체)·비정상 캔들색·%R 다이버전스. auto-vwap에는 알림(`alertcondition`)이 없습니다. 테이블은 20행 → **18행**(추세 전환가 6→4행)으로 줄었다가, 배열 전환 2행 분리로 현재 **19행**(추세 전환가 5행)입니다.

> 미반영(제안서 선택·비권고 항목): `EMA 전환`(= EMA[1], 중복 정보)·`D/E 전환`(구조상 대부분 도달불가)은 CEO 지시대로 넣지 않았습니다. 기존 ㄱ|ㄴ|ㄷ 값의 툴팁 이관도 하지 않았습니다.

## Sonar 모멘텀 배경

CEO 지시(2026-10-16)로 구 **밴드워킹 배경**을 대체한 차트 배경입니다. 국내 MTS `SonarMomentumSignal강세약세(20,9,9)`를 알고리즘 수학자 조사 결과에 따라 이식했습니다. 매매 신호가 아니라 **표시 전용 모멘텀 국면 표식**이며, 이치모쿠·테이블과의 교차 검증용입니다.

```pine
sonarEma    = ta.ema(close, n)              // n = Sonar EMA 기간(기본 20)
sonar       = sonarEma - sonarEma[k]        // k = 비교 간격(기본 9) — 키움 영웅문 차분형 정의
sonarSignal = ta.ema(sonar, m)              // m = Signal 기간(기본 9)
diff        = 판정 기준 == "0선" ? sonar : sonar - sonarSignal
상태        = diff > 0 → 상승(+1) / diff < 0 → 하락(−1) / diff == 0 → 이전 상태 유지 (var 래치)
```

- **판정 기준(옵션).** `Signal 교차`(기본) = Sonar가 Signal 위면 상승, 아래면 하락. `0선` = Sonar가 0 위면 상승, 아래면 하락. ⚠️ **원 MTS 판정식은 공개되지 않았습니다 — `Signal 교차`는 유력 추정**이며 `0선`은 대안 가설입니다. 원 지표와 색이 다르게 보이면 `0선`으로 바꿔 대조하세요.
- **색.** **상승=녹(#2E7D32)·하락=빨강(#C62828)**, 투명도 **85**(CEO 지시 2026-10-16 — 구 70(밴드워킹 배경 값)보다 연하게, 불투명도 30%→15%). 원 MTS의 빨강=상승·파랑=하락 관례가 아니라 펀드 컨벤션을 따릅니다.
- **칠 영역(옵션).** 기본은 `차트 전체(bgcolor)`입니다(CEO 지시로 구 기본 `밴드 내부`에서 변경). `밴드 내부`는 밴드2(상단2~하단2) 영역 fill로, 구 밴드워킹 배경과 같은 위치·z-order입니다. 밴드2 **선을 꺼도**(`showBand_2` OFF) 밴드 값은 계속 계산되므로 같은 영역을 칠합니다. VWAP가 표시되지 않는 봉(`shouldPlot=false`: 일/주/월봉 숨김 옵션·거래량 0)이나 밴드2 값이 `na`인 봉은 칠하지 않습니다. `차트 전체(bgcolor)`는 원 MTS처럼 차트 전체 세로 배경을 칠하며 VWAP 표시 여부와 무관합니다.
- **소스.** `close` 고정(원 지표가 종가 기준). `리본 소스`(`ribbonSrc`)와는 공유하지 않습니다. 리본 표시 옵션을 바꿀 때 배경 판정이 함께 바뀌지 않게 하려는 것입니다.
- **워밍업.** Sonar는 `n+k−1`번째 봉, Signal은 `n+k+m−2`번째 봉부터 유효합니다. 그 전 구간은 `bar_index` 문턱과 `na` 가드로 **배경을 칠하지 않습니다**(`0선` 모드는 Signal을 기다리지 않음).
- **리페인팅.** 현재봉 종가가 들어가므로 **실시간 봉에서는 틱마다 바뀔 수 있고, 봉 마감 시 확정**됩니다. 확정된 과거봉은 바뀌지 않습니다. `request.security`·`lookahead`·미래 참조가 없고, 과거 참조는 `[k]`(k ≤ 500)뿐이라 `max_bars_back=1000` 안입니다.
- **제거된 것.** 구 밴드워킹 배경 판정(20봉 `computeVwapSet(vwapStateBars)`·`vwOut*`·`vwSlope*`·`vwBwExpanding`·`vwBreak*`·`vwWalk*`·`vwUpperWalk`/`vwLowerWalk`·`bgWalkPaintState`·`bgFillColor`)과 전용 입력(`vwap 상태 전용 최근 봉 수(6상태)`·`정배열/역배열 배경 표시`·`정배열 배경색`·`역배열 배경색`·`배경 투명도`)은 다른 소비처가 없어 삭제했습니다. 이치모쿠 테이블의 `VWAP 상태`(밴드워킹/지지/저항/이탈) 셀은 별도 지표(advanced-ichimoku) 로직이라 영향이 없습니다.

## 레이어(z-order) 순서 — 실제 순서(auto-scale 폭발 버그 수정 반영)

차트에 겹쳐 그려지는 페인팅의 **앞뒤(z-order)** 순서입니다. Pine v6의 렌더 순서는 `explicit_plot_zorder=true`(스크립트 상단 `indicator()`에 지정)에서 **`plot()`/`hline()`/`fill()`의 코드 선언 순서**로 결정됩니다(먼저 선언 = 더 뒤, 나중 선언 = 더 앞). **단 `bgcolor()`는 이 인자와 무관하게 항상 최후면 그룹**이고, **`barcolor()`(비정상 캔들 몸통색)는 봉 몸통에 직접 그려져 `plot`/`fill`과 레이어가 다릅니다**. **비정상 매수/매도는 CEO 지시로 배경(`bgcolor`)에서 캔들 몸통색(`barcolor`)으로 전환**됐으므로, 이제 `plot`/`fill` 간 순서는 아래와 같습니다(뒤 → 앞):

> **캔들과의 관계(`behind_chart=true`, CEO 지시 2026-10-16).** 아래 1~3은 **스크립트 내부** 순서이고, 스크립트 전체는 `indicator(..., behind_chart=true)`로 **메인 캔들 뒤**에 그려집니다(Sonar 배경·VWAP·밴드·리본·VWMA·%R 원·상태 테이블 전부). 공식 문서상 이 인자의 기본값은 이미 `true`이며 코드에는 의도를 명시하려고 넣었습니다. **스크립트 단위 설정**이라 Sonar fill만 따로 뒤로 보낼 수는 없습니다. ⚠️ 선언부 시각 설정은 **차트에 처음 로드될 때만** 적용되므로, 이미 차트에 올린 지표는 **삭제 후 다시 추가**하거나 지표 상태줄 **More(⋯) → Visual order**에서 뒤로 보내야 반영됩니다. `explicit_plot_zorder`(내부 순서)와는 축이 달라 충돌하지 않습니다. 캔들이 VWAP·밴드 선 위를 덮을 수 있고, 상태 테이블이 캔들과 겹치면 캔들이 위에 보일 수 있습니다(TradingView 실차트 확인 필요).

1. **가장 뒤(back-most): 거래량 가중선 50/100/200 + 100~200 fill.** `plot`/`fill` 중에서는 가장 먼저 선언되어 나머지 plot/fill보다 뒤입니다.
2. **가장 앞(front-most): 나머지 모든 페인팅.** VWAP 본선·가격축 라벨, 밴드1/밴드2 + 각 fill, Sonar 모멘텀 배경(`밴드 내부` 모드의 밴드2 영역 fill — `차트 전체` 모드는 `bgcolor`라 이 순서와 무관하게 차트 배경 레이어), 지수 리본(EMA/DEMA/TEMA), 그리고 %R 다이버전스 원(`plotshape`)입니다. `plotshape`와 드로잉(라벨·상태 테이블)은 `explicit_plot_zorder` 영향 밖에서 각자 상위 z-그룹의 최전면을 유지하므로 자동으로 "가장 앞"에 포함됩니다.
3. **레이어 밖(별도): 비정상 매수/매도 캔들 몸통색(`barcolor`).** 봉의 몸통색을 직접 바꾸는 것이라 위 `plot`/`fill` 순서와 별개이며, Sonar 배경(fill/`bgcolor`)과 대상이 달라 겹쳐도 시각 충돌 없이 공존합니다. 색·조건·판정(`abnBarColor`/`abnShowBg`/`abnCandleState`)은 불변.

⚠️ 이 순서는 **색·조건·판정·값·산식을 일절 바꾸지 않고 렌더 매체(비정상 배경 `bgcolor`→캔들 몸통색 `barcolor`)만** 전환한 결과입니다. **최종 표시는 TradingView 컴파일·실차트에서 재확인이 필요합니다(비정상 캔들색이 몸통에만 적용되고 나머지 봉은 기본색 유지되는지).**

## 윌리엄스 %R 다이버전스 원 (독립 지표)

⚠️ **전환 후보 삼각형·꼬리 필터·cRSI 삼각형 필터·중복 억제 래치·%R 방향확인 억제(삼각형용)는 CEO 지시로 로직째 전면 제거**됐습니다. 관련 심볼(`candUp`/`candDn`·`blueShow`/`redShow`·`blueLatched`/`redLatched`·`crsiVal`/`crsiUb`/`crsiDb`·`triLookback`·`bandGate`/`triGate`·`suppressBlue`/`suppressRed`·삼각형 `plotshape`·`triCandBuyColor`/`triCandSellColor`)과 cRSI 삼각형 필터 그룹 input(`cRSI 삼각형 필터 사용`·`cRSI 지배 사이클 길이`·`cRSI 밴드 좁혀짐 임계`·`삼각형·동적밴드 최근 N봉 게이트`)을 전부 삭제했습니다(잔재 0). **윌리엄스 %R 다이버전스는 별개 지표(`ta.wpr` 기반)라 그대로 존치**합니다(아래). 기존 auto-vwap 기능(VWAP·밴드·비정상·리본·테이블·이격도·되돌림)은 전부 불변입니다.

### 윌리엄스 %R 다이버전스(williams-fractal 원본 이식 — 존치)

⚠️ **프랙탈 제거와 무관하게 전부 그대로 유지**합니다(`ta.wpr` 기반 별개 지표, 프랙탈 변수 미참조).

- **%R.** `wpr = ta.wpr(wprLen)`(기본 20, 종가 기준, 범위 −100~0). 오버레이 부적합이라 **라인은 그리지 않고** 다이버전스 봉에 **원 마커**(`offset 0`, 확정된 현재봉)만 표시합니다.
- **강세(매수)=라이트 스카이블루 원(belowbar, `#81D4FA`).** `wpr[1] < wprLower`(직전 봉 하단 밴드 진입, 기본 −80) AND (`close < close[1]` AND `wpr > wpr[1]`) — 과매도 진입 후 종가↓·%R↑.
- **약세(매도)=딥 핑크 원(abovebar, `#FF1493`).** `wpr[1] > wprUpper`(직전 봉 상단 밴드 진입, 기본 −20) AND (`close > close[1]` AND `wpr < wpr[1]`) — 과매수 진입 후 종가↑·%R↓.
- **레이어·리페인팅.** 원 마커는 `plotshape`(offset 0, 확정된 현재봉)로 그립니다. `close[1]`·`wpr[1]`·`wpr` 모두 확정/과거참조라 **리페인팅이 없습니다**.

⚠️ **컴파일 확인 필요.** 로컬 Pine 컴파일러가 없어 정적 리뷰(타입·`na`·`max_bars_back`·plot 개수 상한)로 검증했으며, 최종 동작은 **TradingView 컴파일·차트 확인**이 필요합니다.

## 주의사항

- 이 지표는 거래량 데이터가 있어야 정상 동작합니다. 코드에는 거래량이 없을 때 `runtime.error`도 들어 있습니다.
- VWAP 누적은 **Recent Bars 롤링 단일 방식**으로 고정입니다(앵커모드·세션/거래일 기준 제거).
- `Recent Bars`는 차트 타임프레임의 봉 수 기준이라, 타임프레임을 바꾸면 같은 숫자여도 의미가 달라집니다.
- 저유동 종목에서는 VWAP과 밴드 반응이 더 거칠 수 있습니다.
- 성능: 헤더에 `max_bars_back=1000`을 두어(원본 이치모쿠와 동일 헤드룸) `ta.vwma(close, 200)`+σ 등 200봉 참조의 런타임 오프셋 오류·버퍼 자동확장을 예방합니다(산식 변경 아님).
