# Auto VWAP

트레이딩뷰용 Pine Script 오버레이 지표 설명서입니다.

대상 스크립트:
- [`auto-vwap.pine`](./auto-vwap.pine)

이 지표는 VWAP 누적을 **`최근 N봉 롤링(Recent Bars)` 단일 방식**으로 계산합니다(CEO 지시 — 앵커모드 제거). 이전에는 `현재 세션 기준 VWAP`·`최근 N거래일 기준 VWAP`·`최근 N봉 기준 VWAP`를 앵커모드로 바꿔 볼 수 있었으나, 알고리즘 수학자가 지적한 DRIFT(원본 이치모쿠의 `vwap상태(20)`는 앵커 무관 Recent Bars 고정이 정답) 해소를 위해 **앵커모드 입력·세션/거래일 분기·세션 리셋 로직을 전부 삭제**하고, 전 VWAP(화면 50봉·`vwap상태(20)`·중기추세가 쓰는 `vwapValue`·지지저항 등)이 Recent Bars 단일로 계산되게 했습니다. 핵심은 `평균 체결 단가가 어디인지`, 그리고 `현재 가격이 그 기준에서 얼마나 멀리 벗어났는지`를 빠르게 읽는 데 있습니다.

## 현재 소스 기준으로 보이는 것

| 요소 | 현재 표시 방식 |
| --- | --- |
| VWAP | 선택한 기준 구간의 거래량 가중 평균 단가입니다. |
| Band #1 | VWAP 대비 1차 확장 구간입니다. |
| Band #2 | VWAP 대비 2차 확장 구간으로, 과확장 감시에 더 가까운 선입니다. |
| 밴드 계산 타입 | `Log Standard Deviation`, `Absolute Standard Deviation` 중 선택합니다. |
| 누적 방식(고정) | **최근 N봉 롤링(Recent Bars) 단일 방식**입니다(CEO 지시 — 앵커모드 제거). 세션/거래일 앵커 분기·세션 리셋 로직은 삭제됐고, VWAP는 항상 최근 `N`봉 누적 구간을 하나의 이동 창처럼 계산합니다. 세션 경계를 무시하고 현재 타임프레임의 봉 수 기준으로 바로 계산합니다. |
| VWAP 세트 | VWAP·밴드·밴드2는 **단일 화면 세트**로 계산합니다 — window 길이 `Recent Bars = 50`(기본), 소스 `Source`(기본 `hlc3`), 화면 plot·밴드·라벨의 기준입니다. VWAP 계산 헬퍼(`computeVwapSet`)가 window 길이(롤링 길이)와 소스를 인자로 받아 **Recent Bars 롤링(앵커 = `barsLen`봉 전 누적)** 으로 확정봉 기준 누적하므로 리페인팅이 없습니다. |
| 선 굵기·가격축 | VWAP 중앙선은 **2px**이며(CEO 지시 — 지지/저항 색 규칙). 색 구성은 VWAP 값을 두 plot으로 나눠, 동적 색 선(녹/빨강/흰)과 흰색 고정 가격축 라벨을 분리하는 구조입니다(선은 pane에 1회만 그려져 중복선 없음). **VWAP 중앙선의 가격축 라벨은 선색과 무관하게 항상 흰색으로 고정**되도록 별도 plot(제목 `VWAP 가격축 라벨`)으로 흰색만 담당하며, 지지/저항 색 옵션 ON/OFF와 무관합니다. ⚠️ **기본 표시(Style 탭) 상태는 아래 "기본 표시 옵션" 행 참조** — VWAP 본선·VWAP 가격축 라벨·Band #1은 CEO 지시로 **기본 OFF**입니다(색·산식·판정 로직은 불변, plot의 `display` 인자만 조정). |
| 기본 표시 옵션(Style 탭 기본 체크) | 차트에 지표를 처음 얹었을 때의 **기본 표시 상태**입니다(사용자가 Style 탭·설정에서 각자 켜고 끌 수 있음, 값·조건·색·산식은 전부 불변 — plot의 `display` 인자만 설정). **기본 OFF(`display.none`)**: **브이왑(VWAP 본선)**·**VWAP 가격축 라벨**·**Upper Band #1**·**Lower Band #1**(CEO 지시). Band #1은 plot의 `display`를 `display.none`으로 직접 고정했으며, `showBand_1` 입력 토글과 밴드1 %갭 라벨(`showBand_1` 조건) 로직은 불변입니다. Band #2·리본·이격도 등 다른 plot의 기본 표시는 변경하지 않았습니다. |
| VWAP 선 지지/저항 색 | `VWAP 선 지지/저항 색(구간 종가·꼬리 걸침 이탈)` 옵션(기본 **ON**)이 켜져 있으면 화면 VWAP 중앙선(`vwapValue`)의 색을 **봉 단위**로 칠합니다(CEO 확정 규칙). **"near 구간"** = VWAP와 밴드1 사이의 **동적 %(pct) 범위**입니다(밴드1 전체가 아님). 하단 near `[lowerNear, vwap]`, 상단 near `[vwap, upperNear]`. **`upperNear = vwap + pct×(upperBand1 − vwap)`**, **`lowerNear = vwap − pct×(vwap − lowerBand1)`** — 저항(하단)·지지(상단) **동일 pct 대칭**. **`pct`(구간 비율)는 밴드폭 반비례 동적**입니다: 밴드폭이 **좁을 때(저변동성) 최대 0.60(60%)**, **넓을 때(고변동성) 최소 0.20(20%)**로 수렴합니다. 산식은 `bandWidth1 = upperBand1 − lowerBand1`, `r = bandWidth1 / vwap`(가격 대비 밴드폭 비율, 종목·가격 무관), `t = clamp((r − rLow)/(rHigh − rLow), 0, 1)`, `nearPct = maxPct − t×(maxPct − minPct)`, `pct = clamp(nearPct, 0, 100)/100`입니다 — `r ≤ rLow`(저변동성·좁은밴드)면 `maxPct`(넓은 near), `r ≥ rHigh`(고변동성·넓은밴드)면 `minPct`(좁은 near), 사이는 선형보간(반비례). 기본값은 `VWAP 근처 구간 최소 %(넓을 때)=20`·`최대 %(좁을 때)=60`·`저변동성 임계=0.5%`·`고변동성 임계=2.0%`입니다(임계 뒤집힘·`vwap==0`이면 `t=0` → 최대% 폴백). 색 규약: **지지=녹 / 저항=빨강 / 중립=흰**. 규칙은 다음과 같습니다 — **저항=빨강**(`UPPER_BREAK_LINE_COLOR`) = **① `lowerNear ≤ close ≤ vwap`**(하단 near 안에 종가 마감 = VWAP이 저항) **OR ② `close < lowerNear` AND `high > lowerNear`**(종가는 하단 near 아래로 이탈했지만 **고가**가 하단 near 최저 위 = 꼬리 걸침 되밀림); **지지=녹**(`LOWER_BREAK_LINE_COLOR`) = **③ `vwap ≤ close ≤ upperNear`**(상단 near 안에 종가 마감 = VWAP이 지지) **OR ④ `close > upperNear` AND `low < upperNear`**(종가는 상단 near 위로 이탈했지만 **저가**가 상단 near 최고 아래 = 꼬리 걸침 되밀림); **그 외**(완전 이탈: `close`가 near 구간 밖이고 꼬리도 near에 안 걸침 / 워밍업 `na`) → **중립=흰**(`DEFAULT_LINE_COLOR`). **`close == vwap` 경계**: ①은 `close ≤ vwap`, ③은 `close ≥ vwap`이라 `close == vwap`이 양쪽에 걸립니다 — **저항을 먼저 평가**(코드에서 `if 저항 → else if 지지`)해 `close == vwap`이면 **저항=빨강**으로 확정합니다(부동소수라 실제 동일값은 드묾). **상호배타·미정의 구멍 없음**: ②(`close<lowerNear`)와 ①(`close≥lowerNear`) 배타, ④(`close>upperNear`)와 ③(`close≤upperNear`) 배타, 저항 계열(`close≤vwap` or `close<lowerNear`)과 지지 계열(`close≥vwap` or `close>upperNear`)은 `close==vwap` 외엔 배타이며 `close==vwap`은 위 우선순위로 저항 단일 확정 → 전 조합이 정확히 한 색으로 결정됩니다. **②④의 의미**: ②는 "종가가 하단 near 아래로 이탈했지만 아래꼬리가 아니라 **위꼬리(고가)가 하단 near에 걸쳐 되밀린** 봉"을 저항으로, ④는 "종가가 상단 near 위로 이탈했지만 **저가가 상단 near에 걸쳐 되밀린** 봉"을 지지로 인정합니다(순수 종가 이탈이라도 꼬리가 near를 관통했으면 지지/저항 신호로 봄). **엣지케이스**: 밴드1 편차 0(완전 도지)이면 `bandWidth1=0` → `r=0(≤rLow)`이라 pct=최대나 `upperNear=lowerNear=vwap`로 near 구간이 소멸 — 종가가 그 값이면 ① 해당(저항), 아니면 꼬리(high/low)로 ②④ 판정. 이 색은 봉 단위 series color라 **과거 봉은 값이 확정돼 리페인팅이 없고**, 형성 중 현재봉만 종가/고저 확정 전 색이 바뀔 수 있다가 봉 마감 시 확정됩니다(과거 변조 아님). 판정에 쓰는 `close`·`high`·`low`·`vwap`·밴드1·near는 모두 확정봉 세트값입니다. 색 우선순위: 지지/저항 규칙이 ON이면 이 규칙이 VWAP 선 색을 담당하고, OFF이면 아래 `Enable Dynamic Line Color` 거동(밴드2 이탈 녹/빨강, 기본 흰색)을 따릅니다. |
| 선 색상 변화(밴드2 이탈) | `Enable Dynamic Line Color`를 켜면 `Band #2` **이탈 시** 하단 아래 녹색·상단 위 빨간색으로 읽습니다(기본 흰색). 이 옵션은 `Band #1`에 적용되며, VWAP 선에는 위 `VWAP 선 지지/저항 색`이 **OFF일 때만** 적용됩니다(ON이면 지지/저항 규칙이 우선). 두 색 규칙은 서로 독립입니다. |
| 최외곽 선(`Band #2`) 색·두께 | `Upper/Lower Band #2`(±2σ, 최외곽 선)는 **위치가 항상 밴드2 원값(VWAP±2σ)에 고정**되며(이치모쿠 밴드처럼 위치 불변), 선 두께는 **기본 1px 대시(dashed)**입니다. **선 색은 활성 기본색(`activeLineColor`) 고정**입니다(상·하단 두 선 동일). ⚠️ **롤백(CEO 지시)**: 직전에 넣었던 "밴드2 선색을 `paintState`(정/역배열)에 따라 순수 녹/빨강으로 바꾸는" 조건식을 **완전히 제거**하고 원래대로 `activeLineColor`(무조건)로 환원했습니다. 그에 따라 신설했던 input `band2BullLineColor`/`band2BearLineColor`도 **삭제**했고(참조 끊김), 그 순수 녹(`rgb(0,255,0)`)/빨강(`rgb(255,0,0)`) 색값은 아래 "실시간 상승/하락 전환 수평선"으로 **이관**해 재사용합니다. 위 `Enable Dynamic Line Color`(녹/빨강 이탈 표시)는 VWAP 선·`Band #1`에 적용되며 이 밴드2 선과는 별개입니다. 밴드2 **값·산식·fill(배경 어두운 톤·투명도·정역배열 배경)** 은 불변이고 선 색만 `activeLineColor`로 환원했습니다. |
| 비정상 매수/매도 캔들색 | `비정상 매수/매도 캔들색 표시` 옵션(기본 **ON**)이 켜져 있으면, **과매수/과매도(비정상) 구간의 해당 봉 캔들 몸통색**을 오버라이드로 칠합니다(SUPER-ICHIMOKU 메인 지표 `advanced-ichimoku.pine`의 "비정상 캔들" 판정 이식). ⚠️ **표현 매체 전환(배경 `bgcolor` → 캔들 몸통색 `barcolor`, CEO 지시)**: 직전까지는 이 비정상 구간을 **화면 전체 세로 배경**(`bgcolor`)으로 칠했으나, CEO 지시로 **해당 봉의 캔들 몸통색**(`barcolor`)으로 옮겼습니다. 비정상 구간에서만 `barcolor(...)`로 몸통을 칠하고, **비정상이 아닌 봉은 `barcolor(na)`로 캔들 기본색을 유지**(오버라이드 안 함)합니다. 색상(hue)은 기존 배경색을 그대로 승계하되, 캔들 몸통은 배경처럼 옅으면(구 배경 투명도 82) 거의 안 보이므로 **불투명(투명도 0)으로 선명히** 칠합니다(구 `비정상 배경 투명도` input은 캔들색엔 부적합해 **삭제**, 새 파라미터는 만들지 않음). **판정(`abnCandleState` 래치)·조건·색상은 불변, 렌더 매체만 `bgcolor`→`barcolor`로 전환.** **z-order(레이어)**: `barcolor`는 봉의 몸통색을 바꾸는 것이라 `plot`/`fill`/`bgcolor`와 **레이어가 다릅니다**(봉 몸통 ↔ 밴드 배경) — 비정상 캔들색과 정/역배열·전환 확정 밴드 배경이 동시에 떠도 서로 다른 대상에 그려져 **시각 충돌 없이 공존**합니다. **판정 = cRSI 과매수/과매도(도미넌트 사이클) + 볼린저 밴드 이탈(고가/저가 기준)** 두 조건 AND. **비정상 매수(=과매수)** = `cRSI ≥ 절대 과매수(70)` **AND** 고가가 볼린저 상단 밴드를 초과(초과폭 ÷ 캔들 범위 ≥ `비정상 밴드 초과 비율`) → **붉은 캔들(`#E53935`, Material Red 500)**(CEO 지시 — 과매수=고점 경고 직관(붉은=위험)에 부합. 직전 주황(`#FF9800`)에서 변경: 하락 전환 후보 배경 주황 `#EF6C00`과 색이 겹쳐 구분 위해 붉은 계열로 이동). **비정상 매도(=과매도)** = `cRSI ≤ 절대 과매도(30)` **AND** 저가가 볼린저 하단 밴드를 이탈(이탈폭 ÷ 캔들 범위 ≥ 비율) → **파랑 캔들**(CEO 명시: 매도=파랑·매수=붉은색). 상태는 **래치**되어 다음 비정상 봉까지 유지되며, **이격도(Disparity)가 중립(되돌림 주의·확실 모두 해소)으로 복귀하면 리셋**됩니다(원본과 동일한 종료 조건). ⚠️ **자기완결 이식**: 원본은 기준 길이를 이치모쿠 베이스 라인(`basePeriods`)에 연동했으나 auto-vwap엔 그 input이 없어, **CEO 지시로 비정상 전체 기준 길이를 단일 input `비정상 기준 길이(볼린저 등)`(기본 20) 하나로 통일**했습니다(구 전용 input `비정상 기준 길이(베이스 라인 대응)`(기본 22)는 삭제). 이 값 하나에 **볼린저 밴드 길이 + cRSI 사이클(이 값÷2=10)·ATR·RSI·반등 ## 트레이딩 의미 핵심 4가지

### 1. 가격이 VWAP 위 / 아래에 있는 의미

가격이 VWAP 위에 있으면 `선택한 기준 구간 평균 단가보다 위에서 거래 중`, 아래에 있으면 `평균 단가보다 아래에서 거래 중`이라고 읽습니다.

- 방향 예측선이라기보다 현재 가격의 `비용대 기준 위치`를 보는 도구입니다.
- 실전에서는 `회복 후 유지`, `이탈 후 재진입 실패` 쪽이 더 중요합니다.

요약하면, VWAP은 `평균 단가 기준선`입니다.

### 2. VWAP 근처 왕복 의미

VWAP 근처를 계속 왕복하면 `방향성 추세`보다 `평균 단가 공방`이 진행 중일 가능성이 큽니다.

- 이 구간에서는 추격 진입보다 방향 확정 대기가 더 낫습니다.
- 다른 지표가 좋아 보여도 VWAP 공방이 길면 후속이 약할 수 있습니다.

요약하면, VWAP 공방은 `판단 유보 구간`으로 보는 편이 안전합니다.

### 3. Band #1 접근 의미

Band #1 접근은 `정상 확장` 또는 `첫 과열 구간`에 더 가깝습니다.

- 추세가 막 붙기 시작하는 구간에서도 자주 나옵니다.
- 따라서 Band #1 자체를 반전 신호로 보기보다 `확장 확인`으로 읽는 편이 좋습니다.

요약하면, Band #1은 `추세 확장 확인선`에 가깝습니다.

### 4. Band #2 접근 의미

Band #2 접근이나 이탈은 `강한 확장`, `과열 / 과매도`, `과확장 감시` 의미가 더 큽니다.

- 강한 추세에서는 바깥 체류가 이어질 수 있습니다.
- 그래서 Band #2는 바로 역방향 진입보다 `속도 조절`, `관리`, `후속 확인` 쪽에 더 유리합니다.

요약하면, Band #2는 `공격`보다 `과확장 감시`의 의미가 강합니다.

## 내부 로직

### 1. 기준 구간 — Recent Bars 롤링 단일 고정

VWAP 누적 방식은 **최근 N봉 롤링(Recent Bars) 하나로 고정**되어 있습니다(CEO 지시 — 앵커모드 제거). 과거의 `Session`/`Recent Trading Days` 앵커 분기와 세션 리셋(`ta.change(time("D"))` 류)·세션 누적 배열은 **완전히 삭제**됐습니다. 알고리즘 수학자가 지적한 DRIFT(원본 이치모쿠의 `vwap상태(20)`는 앵커 무관 Recent Bars 고정이 정답)를 해소하려는 조치이며, 화면 50봉·`vwap상태(20)`·중기추세 `vwapValue`·지지저항 등 **전 VWAP이 Recent Bars 단일로 계산**됩니다.

`Recent Bars`
- 최근 `N`봉(`Recent Bars`, 기본 50)을 하나의 이동 창처럼 계산합니다(앵커 = `N`봉 전 누적값).
- 세션 경계를 무시하고 차트에 보이는 현재 타임프레임 기준 봉 수로 바로 계산합니다.
- 워밍업(봉 수 < `N`)에는 창이 전체 누적으로 자연 폴백됩니다.

### 2. VWAP 계산

현재 코드는 아래 값을 누적해서 씁니다.

- `src * volume`
- `volume`
- `src^2 * volume`

이 누적값으로:
- `VWAP`
- 거래량 가중 분산
- 표준편차 기반 밴드

를 계산합니다.

`computeVwapSet(barsLen, srcArg)` 헬퍼가 window 길이(Recent Bars 롤링 length)와 **소스**를 파라미터로 받아 화면 세트(`length=50`, `src`)를 계산합니다. 누적값(`cumulative*`)은 **함수-로컬 `var`로 내부화**했습니다 — Pine v6에서 함수 내부 `var`는 호출부마다 독립 상태를 가지므로 확정봉 기준으로 누적하며 리페인팅이 없습니다. window = 현재 누적 − `barsLen`봉 전 누적(`cumulative*[barsLen]`)이라 항상 최근 `barsLen`봉 롤링입니다(앵커모드 제거로 세션/거래일 분기·세션 앵커 배열은 삭제됨). 밴드·밴드2도 이 세트의 window에서 산출됩니다. 산식(rolling VWAP + 로그/절대 표준편차 밴드)은 앵커모드 제거 전의 Recent Bars 경로와 동일합니다.

### 3. 밴드 계산 방식

`Bands Calculation Mode`는 두 가지입니다.

`Log Standard Deviation`
- 현재 기본값입니다.
- 거래량 가중 `log(price)` 표준편차를 사용합니다.
- 밴드는 `VWAP * exp(± sigma_log * multiplier)` 형태로 계산되어, 절대 가격보다 비율 변화에 더 민감합니다.
- 가격이 0 이하인 자산에는 적합하지 않습니다.

`Absolute Standard Deviation`
- 거래량 가중 표준편차를 절대 가격 단위로 계산해 밴드 폭으로 사용합니다.

즉 이 지표는 `VWAP 기준선 + 확장 폭 방식`을 바꿔가며 읽는 구조입니다.

> **상태 테이블(재도입):** 이전에는 상태 테이블을 두지 않았으나, SUPER-ICHIMOKU 테이블을 이식해 **우측 상단 상태 테이블을 재도입**했습니다(`상태 테이블 표시` 옵션, 기본 ON — 위 "상태 테이블" 행 참조). 3개 섹션(추세 확인 / 가격 구조 및 변동성 확인 / 지지·저항 확인)으로, 판정식은 이치모쿠 원본 로직 그대로입니다(캔들 상태·캔들 손절라인 행은 미이식). **반등 감시(`abnWatch`)** 는 이제 이 테이블의 `비정상 매수/매도` 행에 "롱 감시/숏 감시"로 표기됩니다(그간 보류했던 표시가 테이블 재도입으로 연결됨). **비정상 매수/매도**는 배경색 + 이 테이블 셀로 함께 표시하며, **이격도**도 래치 리셋 판정에 더해 테이블 `이격도 (20)` 셀로 표기합니다.

### 4. 비정상 매수/매도(과매수/과매도) — 이치모쿠 이식

SUPER-ICHIMOKU 메인 지표(`advanced-ichimoku.pine`)의 **"비정상 캔들"** 판정을 그대로 이식했습니다. 목적은 **평균 회귀가 필요한 극단 구간(과매수/과매도)** 을 배경색으로 한눈에 드러내는 것입니다.

- **cRSI(도미넌트 사이클 RSI)**: 사이클 길이 = `비정상 기준 길이 ÷ 2`(기본 20÷2=10)의 RSI를 Vibration(기본 10)으로 위상 보정·평활한 값. `≥ 절대 과매수(70)`면 과매수, `≤ 절대 과매도(30)`면 과매도.
- **볼린저 밴드 이탈**: `SMA(close, 비정상 기준 길이) ± stdev × 배수(2.0)`. **볼린저 길이는 비정상 전체 기준 길이(`비정상 기준 길이(볼린저 등)`, 기본 20)** 와 동일합니다(CEO 지시로 단일화 — cRSI·ATR·RSI·추적 lookback도 모두 이 값에 연동). 종가가 아닌 **고가/저가**로 판정합니다(종가 실시간 변동이 커서). 상단 초과폭(또는 하단 이탈폭) ÷ 캔들 범위가 `비정상 밴드 초과 비율(0.3)` 이상이면 이탈로 인정.
- **비정상 판정(AND)**: 비정상 매수(=과매수) = cRSI 과매수 **AND** 고가 상단 이탈, 비정상 매도(=과매도) = cRSI 과매도 **AND** 저가 하단 이탈.
- **상태 래치·리셋**: 비정상 봉이 나오면 그 방향 상태를 래치해 다음 비정상 봉까지 유지하고, **이격도(Disparity)가 중립으로 복귀하면 리셋**합니다. 이격도 = `종가 ÷ 이평(기본 SMA 20) × 100`으로, 고정 임계(±10%)와 적응형(자기 표준편차 σ×1.5) 두 기준의 충족 개수로 되돌림을 판정하며, **둘 다 미충족(중립)이면 리셋 트리거**입니다.
- **반등 감시(abnWatch) — 이치모쿠 반등 감시 이식(CEO 지시)**: 비정상 캔들(극단) 발생 뒤 **그 방향과 반대되는 되돌림(반등)** 이 유의미하면 **`abnWatch` 상태**(`+2`=롱 감시, `−2`=숏 감시, `0`=없음)로 래치합니다. 판정 = 비정상 캔들이 뜬 봉의 극단가(롱=`low`·숏=`high`)·RSI·ATR을 기준점(`Ref*`)으로 스냅샷한 뒤, **`abnLookback`(=`비정상 기준 길이`) 봉 이내**에서 ① 반대방향 가격 되돌림(`priceMove`, 롱=`RefPrice−low`·숏=`high−RefPrice`) ≥ `RefAtr × 비정상 반등 감시 ATR 배수`(기본 **1.5**) **AND** ② RSI 되돌림 폭(`rsiMove`) ≤ `비정상 RSI 이동 제한`(기본 **15**)이면 감시 ON. RSI·ATR은 이치모쿠 원본과 동일 길이(`ta.rsi(close, abnLen)`·`ta.atr(abnLen)`, `abnLen=비정상 기준 길이`)이며, 이치모쿠의 **기본/강화 2단 감시는 단일 감시로 통합**된 최신본을 이식했습니다. 리셋은 비정상 상태와 함께 **이격도 중립 복귀 시** `abnWatch`도 `0`으로 돌립니다. ⚠️ **리페인팅 방지(CEO 명시)**: 이치모쿠 원본은 실시간 '빠른 캐치'를 위해 확정봉 가드를 의도적으로 안 걸었으나, 본 이식은 CEO 지시대로 **기준점·감시 래치·리셋을 모두 확정봉(`barstate.isconfirmed`)에서만 갱신**합니다(형성 중 현재봉이 래치를 흔들지 않음 → 신규 리페인팅 없음). 이 실시간성 차이는 CEO 보고 대상입니다. ⚠️ **화면 표시 보류(CEO 판단 대기)**: auto-vwap엔 상태 테이블/셀이 없어(아래 "상태판 없음") 이치모쿠처럼 셀 텍스트("롱 감시"/"숏 감시")로 표기할 자리가 없습니다. 억지로 새 UI를 만들지 않고 **로직만 이식(abnWatch 계산·래치까지)** 했으며, 표시 방식(마커/라벨/셀 등) 확정은 CEO 판단을 기다립니다. `abnWatch` 상태는 이미 계산·래치되어 있어 표시 방식 확정 시 즉시 연결 가능합니다. `비정상 반등 감시 ATR 배수`·`비정상 RSI 이동 제한`은 전략성 파라미터(수학자 리뷰 대상)입니다.

⚠️ **자기완결 이식 근거**: 원본은 기준 길이를 이치모쿠 베이스 라인(`basePeriods`)에, 리셋을 이치모쿠 이격도 블록에 의존했습니다. auto-vwap엔 그 둘이 없으므로 (1) 기준 길이를 **단일 input(`비정상 기준 길이(볼린저 등)`, 기본 20)** 하나로 통일하고(CEO 지시 — 볼린저 + cRSI·ATR·RSI·추적 lookback이 모두 이 값에 연동. 구 별도 `비정상 기준 길이(베이스 라인 대응)` 기본 22는 삭제·통합해 전 기준 길이 22→20으로 통일), (2) 이격도를 **원본 산식·input 그대로 이식**해 자기완결화했습니다. 소스가 같은 기본값이면 원본과 동일한 값을 재현합니다. 반등 감시(`abnWatch`)도 원본 산식(기준점·되돌림 게이트·부호 체계 ±2)을 그대로 이식했고, 두 신설 input(`비정상 반등 감시 ATR 배수`·`비정상 RSI 이동 제한`)은 **title을 이치모쿠와 일치**시키되 auto-vwap의 UI 일관성을 위해 기존 `비정상 매수/매도` 그룹에 배치했습니다(원본 그룹명은 `비정상 캔들`). 매매 신호가 아니라 **표시 전용 국면 표식**이며, 임계·기간은 전략성 파라미터라 임의 변경 시 수학자 리뷰 대상입니다.

## 지수 추세 리본(EMA/DEMA/TEMA) + 정배열/역배열 배경

CEO 설계로 추가한 **지수형 추세 리본**과 그 리본으로 판정하는 **정배열/역배열 배경**입니다. 매매 신호가 아니라 **표시 전용 국면 표식**이며, 기존 auto-vwap 기능(VWAP·밴드·비정상)은 전부 불변입니다.

### 1. 리본 3선(EMA/DEMA/TEMA)

- **계산(종가 기준, 화면 표시 대상).** 단일 소스 `close`에 EMA를 3중 누적합니다: `e1 = EMA(close, 지수 리본 길이)`, `e2 = EMA(e1, 지수 리본 길이)`, `e3 = EMA(e2, 지수 리본 길이)`. 여기서 **`EMA = e1`, `DEMA = 2·e1 − e2`, `TEMA = 3·e1 − 3·e2 + e3`**를 파생합니다. `지수 리본 길이` 기본 **20**. **화면에 그려지는 것은 이 종가 기준 3선뿐**입니다.
- **의미.** DEMA는 EMA의, TEMA는 DEMA의 지연을 각각 줄인 지수형 추세선입니다. 상승 추세가 붙으면 **TEMA > DEMA > EMA(정배열)**, 하락 추세면 역배열로 벌어지며, 세 선의 상대 위치·기울기가 추세 국면을 압축해 보여줍니다.
- **표시.** 각 선 **1px**, 색은 옵션(`EMA 선 색`=노랑 / `DEMA 선 색`=하늘색 / `TEMA 선 색`=분홍). **우측 가격축 라벨 없음**(`display.all − display.price_scale` — 차트 선만, 가격축 숫자 라벨 끔). `지수 추세 리본 표시(EMA/DEMA/TEMA)` 토글(기본 **ON**).
- **리페인팅 없음.** `ta.ema` 누적(확정 성격)이라 과거봉 값이 확정되어 신규 리페인팅이 없습니다.

### 2. 밴드 배경 (전환 셀 상태 + 기울기 3행 컨플루언스 — CEO 재정의)

밴드2(상단2~하단2) 영역 fill 색을 **상태 테이블의 "상승/하락 전환 셀 색"과 "기울기 3행(EMA/DEMA/TEMA) 셀 색"의 컨플루언스**로만 결정합니다(CEO 재정의). 옛 억제/래치/플립 배경 로직(`interimState`/`paintState`·`bullCand`/`bearCand`·`greenSuppress`/`redSuppress`·패턴 무조건 억제 `bgPaintState`)은 **전면 제거**됐고, 배경은 이제 아래 3규칙만 참조합니다.

**새 배경 규칙(3규칙).**

- **① 빨강 배경** = 하락 전환 셀이 빨강(하락 전환 상태) **AND** 기울기 1~3행 셀 중 녹색이 **하나도 없음**.
- **② 녹색 배경** = 상승 전환 셀이 녹색(상승 전환 상태) **AND** 기울기 1~3행 셀 중 빨강이 **하나도 없음**.
- **③ 그 외** = 배경 없음. ①②는 전환 셀 상태(하락 vs 상승)가 배타라 동시발생이 없습니다.

**규칙 입력 두 가지(모두 이미 존재하는 표시의 상태를 읽음).**

- **전환 셀 색(밴드 배경 규칙 입력 = `baseState`).** 밴드 배경 규칙이 읽는 "상승/하락 전환 셀 색"은 `baseState` 기준입니다 — 상승 전환 셀이 녹 = `baseState == 1`, 하락 전환 셀이 빨강 = `baseState == -1`. `baseState`는 종가 리본선(`emaLine`/`demaLine`/`temaLine`)의 현재봉 `[0]−[1]` 기울기 서열(`slopeEma < slopeDema < slopeTema` → 1, `>` → −1, 그 외/na → 0)이며, **전환선·전환 임계 게이트·밴드 배경 규칙 입력에서 공유되므로 남깁니다**(배경 로직 자체는 아님). ⚠️ **테이블 전환 2행의 셀색·활성표시는 `baseState`가 아니라 이 규칙의 최종 결과 `bgFillState`로 게이트**합니다(CEO 버그수정) — 밴드 배경과 정확히 일치시키기 위함이며, 그 결과 `baseState==±1`이지만 기울기 컨플루언스가 어긋나 `bgFillState==0`이면 테이블 전환 행은 중립이 됩니다.
- **기울기 셀 색(테이블 기울기 3행 `f_angle3Color`와 동일 판정).** 각 행(EMA/DEMA/TEMA)의 표시 순서 각도 `v1 = slope3각`·`v2 = slope2각`·`v3 = slope1각`에 대해 **`v1 < v2 < v3` → 녹(정배열)**, **`v1 > v2 > v3` → 빨강(역배열)**, **그 외/na → 회색**(녹도 빨강도 아님)입니다. 배경은 이 3행 각각의 green/red 불리언을 OR로 모아 **"기울기 중 녹 있음 / 빨강 있음"**을 판정합니다: `녹 하나도 없음 = not(emaAngGreen or demaAngGreen or temaAngGreen)`, `빨강 하나도 없음 = not(emaAngRed or demaAngRed or temaAngRed)`.

**기울기 셀 판정의 정합(각도 ↔ raw slope).** 각도는 `atan(slope / ref)`이고 `ref = angleAtrRef = ltAtrTable = ta.atr(14)` 현재봉[0](CEO 지시로 `[1]`→`[0]` 시프트)가 양수(`> 0`)일 때 **단조증가 변환**이라, 각도 순서 비교(`v1<v2<v3` 등)는 **raw slope 순서 비교와 동치**입니다. 그래서 배경 블록에서는 각 라인의 raw 차분(`emaSl3 < emaSl2 < emaSl1` 등)으로 동일 판정을 재현합니다. ⚠️ **선언 순서**: `f_angle3Color`·`angleAtrRef`는 배경 fill보다 아래에서 선언되므로, 배경용 판정을 fill 앞(리본 계산 직후)에서 자체 계산합니다. `ref`가 `na` 또는 `≤ 0`이면 `f_angle3Color`는 회색이 되므로, 배경도 `bgAngleValid = not na(bgAngleRef) and bgAngleRef > 0` 가드로 그 경우 green/red 둘 다 false가 되게 해 **테이블 셀색과 완전 일치**시킵니다. 워밍업에서 `line[3]` 등이 `na`면 slope 차분이 `na` → 부등식 false → 해당 행 녹/빨강 아님(회색), 이 역시 `f_angle3Color`의 na 회색과 일치합니다.

```
// 배경 판정용 ATR 참조 — 테이블 angleAtrRef(=ta.atr(14) 현재봉[0])와 동일 series(선언 순서 회피용 자체 계산).
bgAngleRef = ta.atr(14)
bgAngleValid = not na(bgAngleRef) and bgAngleRef > 0
// 각 리본선의 표시 순서 세 slope(오래된→최신). 각도 순서와 동치.
emaSl1 = emaLine - emaLine[1]   // slope1(현재봉[0] 포함·최신)
emaSl2 = emaLine[1] - emaLine[2]
emaSl3 = emaLine[2] - emaLine[3] // slope3(가장 오래됨)
// (DEMA/TEMA 동일)
emaAngGreen = bgAngleValid and emaSl3 < emaSl2 and emaSl2 < emaSl1
emaAngRed   = bgAngleValid and emaSl3 > emaSl2 and emaSl2 > emaSl1
// (dema*/tema* 동일)
bgAnyAngleGreen = emaAngGreen or demaAngGreen or temaAngGreen
bgAnyAngleRed   = emaAngRed   or demaAngRed   or temaAngRed
// CEO 3규칙: baseState(전환 셀) + 기울기 컨플루언스.
bgFillState = (baseState == -1 and not bgAnyAngleGreen) ? -1
    : (baseState == 1 and not bgAnyAngleRed) ? 1
    : 0
```

`bgFillState = 1(녹 배경) / −1(빨강 배경) / 0(배경 없음)`. fill이 이 값을 참조합니다.

**전환 후보(선행 표시) — 확정(±1)/후보(±2) 확장 `bgFillStateExt`(신규·수학자 확정·CEO 승인).** ⚠️ **기본 모드에서도 화면이 의도적으로 바뀝니다(전환 후보 셀 추가 — CEO 승인 신기능).** 밴드 배경 컨플루언스가 아직 안 붙었을 때(`bgFillStateGated == 0`) **종가가 전환 임계가를 이미 돌파**하면 "후보(미확정 임박)"로 **전환행 셀을 선행 표시**합니다(기본·ATR 정규화 두 모드 공통). ⚠️ **후보 밴드 배경은 CEO 지시로 표시하지 않습니다("어지럽다")** — 밴드 배경은 확정(±1)일 때만 칠하고, 후보는 전환행 셀색(상승=파랑·하락=주황)으로만 확인합니다. 판정은 **새 임계 파라미터 없이 부등호만** 얹습니다(과최적화 자유도 0):

```
bgNeutral = bgFillStateGated == 0
candUp = bgNeutral and upOk and (close > xUp)   // 상승 후보(종가가 녹 진입 최소가 xUp 상향 돌파)
candDn = bgNeutral and dnOk and (close < xDn)   // 하락 후보(종가가 빨강 진입 최대가 xDn 하향 돌파)
candState = (candUp and candDn) ? 0 : candUp ? 2 : candDn ? -2 : 0   // 둘 다=방어코드(정상 미발생)
// 확정 우선(±1 있으면 그대로), 없을 때만 후보(±2) 얹음.
bgFillStateExt = (bgFillStateGated != 0) ? bgFillStateGated : candState
// 도메인: −2(하락후보) / −1(하락확정) / 0(중립) / +1(상승확정) / +2(상승후보)
```

- **모드 무관(두 모드 동일 소스).** `xUp`/`xDn`/`close`는 기본·ATR 정규화 모드에서 동일 소스라 부등호 판정 하나로 두 모드 모두 커버합니다(`useNormSlope` 미참조). `upOk`/`dnOk`(가격 양수·`ribValid`) 게이트 필수.
- **확정 우선·상호배타.** `bgFillStateGated`가 확정(±1)이면 후보를 얹지 않습니다(확정 우선). `candUp`·`candDn` 동시 성립은 `xDn < xUp`이라 종가가 둘 다 넘을 수 없어 논리상 미발생 — 그래도 방어코드로 `0` 처리.
- **raw 게이트 불변.** `xr1/xr2/xUp/xDn`·`baseState`·`bgFillState`·`bull/bearAccel` 등 **raw 계산 라인은 전혀 건드리지 않고**, 후보는 그 하류에서 배경 fill·전환행 셀색 **표시에만** 얹습니다.
- **리페인팅(의도·정상).** `close[0]`·`xUp`/`xDn` 모두 현재봉 라이브값이라 후보 상태는 라이브 봉 동안 깜빡일 수 있습니다(기존 배경·전환선과 동일 특성, 과거봉은 확정·비리페인팅). **표시 전용, 매매 신호 아님**(새 리페인팅 도입 아님).

- **리페인팅 특성(현재봉[0] 실시간·깜빡임 감수·CEO 인지).** 기울기 `slope2`/`slope3`은 확정봉 차분(라이브 봉 내내 불변)이나, 기울기 셀 판정에 쓰는 `slope1`은 **현재봉 `[0]`을 포함**하므로 배경도 라이브 봉 동안 갱신됩니다 — **테이블 기울기 3행과 100% 동일한 값·거동**입니다(봉 마감 시 확정, 과거봉은 확정 후 고정). `baseState`도 현재봉 `[0]−[1]` 기준이라 라이브 봉 동안 갱신됩니다(밴드 배경이 캔들과 정렬돼 현재봉[0] 실시간).
- **배경(밴드2 영역 한정 fill).** `upperBand_2`/`lowerBand_2` 두 선 사이 영역을 반투명(기본 투명도 **70**, `ribbonBgTransp`)으로 채웁니다. ⚠️ **fill 색 게이트는 `bgFillState`(→`bgFillStateGated`) → `bgFillStateExt`(확정 ±1 + 후보 ±2)입니다**(전환 후보 상태 반영). ⚠️ **[후보 밴드 배경 제거 — CEO 지시]** 후보 밴드 배경이 "어지럽다"는 CEO 지시로, **밴드 배경은 확정(±1)일 때만** 칠하고 후보(±2)는 **배경을 칠하지 않습니다(na)**. 후보는 아래 "전환행 셀색"으로만 확인합니다. 색 매핑: `+1`(상승 **확정**) → **녹**(`ribbonBullBgColor #2E7D32`) / `−1`(하락 **확정**) → **빨강**(`ribbonBearBgColor #C62828`) / `+2`(상승 **후보**) → **`na`(배경 없음)** / `−2`(하락 **후보**) → **`na`(배경 없음)** / `0` → `na`(없음). ⚠️ **직전엔 후보도 파랑/주황 밴드 배경을 칠했으나, 이 후보 배경 색칠만 제거**했습니다(±2 분기를 `na`로). 이제 밴드 배경만 봐도 뜨면 곧 확정(상승=녹·하락=빨강)입니다. **판정 로직(`bgFillStateExt`·`candUp`/`candDn`·`baseState`·게이트)은 전부 불변**(이번 변경은 배경 fill의 색 매핑에서 ±2를 `na`로 만든 것뿐)이며, `bgFillStateExt` 상태값·후보 색 상수(`candBgUpColor`/`candBgDnColor`)는 전환행 셀색이 계속 참조하므로 유지됩니다. 확정 색·투명도·z-order·fill 위치는 불변, `showRibbonExpBg`·`shouldPlot`·밴드2 `na` 가드가 표시/워밍업을 방어합니다. `bgcolor`가 아니라 밴드2 영역 한정 `fill`로 그리는 방식도 불변입니다. ⚠️ **밴드2 선(plot) 색은 `activeLineColor`(무조건) 고정으로 롤백**됐습니다 — 신설 input `band2BullLineColor`/`band2BearLineColor`는 **제거**됐고, 그 순수 녹/빨강 색값은 아래 "실시간 상승/하락 전환 수평선"으로 이관됐습니다. 밴드2 값·산식·fill(배경)은 불변.
- **전환행 셀색(확정/후보 구분 — 파랑/주황).** 상태 테이블 "상승/하락 전환" 2행의 값 셀 배경은 `bgFillStateExt`로 확정/후보를 색으로 구분합니다(모두 투명도 **30**으로 통일): **상승** — `+1`(확정)=청록 `ltUpColor #0E9C8A`, `+2`(후보)=**파랑 `candBgUpColor #1565C0`**(Material Blue 800), 그 외=중립 회색(`color.gray` 40). **하락** — `−1`(확정)=자홍 `ltDownColor #C2185B`, `−2`(후보)=**주황 `candBgDnColor #EF6C00`**(Material Orange 800), 그 외=중립 회색. ⚠️ **후보 색 상수(`candBgUpColor`/`candBgDnColor`)는 이제 전환행 셀색 전용**입니다 — 직전엔 밴드 후보 배경과 공유했으나, 후보 밴드 배경이 CEO 지시로 제거되어(위 "배경" 항 참조) 이 상수는 셀색에서만 쓰입니다. 톤앤매너: 후보색은 확정 셀과 **동일 투명도(30)·유사 채도/명도 레벨**로 맞추되 색상(hue)만 다르게 골라 튀지 않게 했고, 확정색(청록/자홍) 및 확정 밴드 배경 녹(`#2E7D32`)/빨강(`#C62828`)과 명확히 구분됩니다. ⚠️ **후보 행 텍스트는 비활성이라 임계가격+%(raw) 그대로 표기**합니다(활성 각도차/정규화갭으로 바꾸지 않음 — 임박 상태이지 확정 아님). 즉 `upText`/`dnText`는 확정(`bgFillStateGated`) 게이트를 유지하고, 셀색만 후보(`bgFillStateExt`)로 파랑/주황을 얹습니다. **판독 규칙(후보는 셀색 전용, 밴드 배경은 확정만): 상승 후보 = 밴드 배경 없음 + 전환행 파랑 셀 / 상승 확정 = 녹 배경 + 청록 셀 / 하락 후보 = 밴드 배경 없음 + 전환행 주황 셀 / 하락 확정 = 빨강 배경 + 자홍 셀.**
- **실시간 상승/하락 전환 수평선 + 프라이스 스케일 라벨(신규).** 배경 전환 임계가격(`xUp`/`xDn` — 상태 테이블 "상승/하락 전환" 2행과 동일 산식)을 차트에 **수평선 + 우측 프라이스 스케일 라벨**로 그립니다. 색: 상승 전환 선 = **순수 녹 `rgb(0,255,0)`**(input `transUpLineColor`), 하락 전환 선 = **순수 빨강 `rgb(255,0,0)`**(input `transDnLineColor`), 표시 토글 `실시간 상승/하락 전환 수평선 표시`(input `showTransitionLines`, 기본 **OFF**). **상태별 표시·가격(게이트는 `baseState` 기준 — 슬로프 순서 전이 임계가격 산식과 정합해 유지. ⚠️ 테이블 전환 2행은 CEO 버그수정으로 `bgFillState` 게이트로 바뀌었으나, 이 차트 수평선은 임계가격 자체라 `baseState`를 유지 — 선엔 "전환 중" 텍스트가 없어 텍스트 모순 없음. 선까지 `bgFillState`로 맞출지는 별도 판단·본부장 검토 대상)**: `상승 전환 선 가격 = baseState==0 ? xUp : baseState==-1 ? xDn : na`(정배열=1이면 숨김), `하락 전환 선 가격 = baseState==0 ? xDn : baseState==1 ? xUp : na`(역배열=−1이면 숨김) — 즉 **중립(0)**=상승(녹·`xUp`)·하락(빨강·`xDn`) 둘 다, **정배열(1·녹)**=하락 전환 선만(=`xUp`, 녹 이탈 하방·상승 선 숨김), **역배열(−1·빨강)**=상승 전환 선만(=`xDn`, 빨강 이탈 상방·하락 선 숨김). `xUp`은 `upOk`, `xDn`은 `dnOk`(na·비양수 방어) 미충족 시 해당 선/라벨 숨김. ⚠️ **가격축 라벨은 대응하는 선과 값·색·게이트를 완전 일치시킴(CEO 지시 — 선-라벨 어긋남 버그 수정)**: 이전에는 라벨 plot을 `baseState==0`(중립)일 때만 값 표시하도록 별도 게이트했으나, `display.price_scale` plot은 값이 `na`가 돼도 **직전 non-na 라벨을 지우지 않고 잔류**시킨다(라벨은 마지막 non-na 값 위치에 남고 색만 현재 봉 기준). 그래서 전환 중(baseState≠0)엔 현재 그려지는 선(상태별 매핑값)과 **다른 과거 가격·색 라벨이 잔류**해 "녹색 선인데 빨간 라벨·엉뚱한 가격"으로 보이는 **선-라벨 값/색 어긋남 버그**가 있었다. → **수정**: 라벨 plot 2개를 `showTransitionLines`일 때 **각각 대응하는 선과 동일한 가격 변수(`상승 라벨 = transUpPrice`·`하락 라벨 = transDnPrice`)·동일 색(`상승 = transUpLineColor` 녹·`하락 = transDnLineColor` 빨강)**을 참조하도록 통일하고 별도 `baseState==0` 게이트를 제거했다. 이러면 **선이 `na`로 사라지는 봉에서 라벨 값도 `na`가 돼**, 라벨이 항상 현재 그려지는 선과 같은 값·색만 표시하고 반대편·과거 잔류 라벨이 현재 선과 모순되지 않는다(중립=두 선+두 라벨, 정배열=하락 선+하락 라벨만, 역배열=상승 선+상승 라벨만). ⚠️ **선(`line.new` 수평선)의 가시성·값은 위 매핑 그대로 불변**입니다(전환 임계 산식·`baseState`·상태별 매핑·색 정의 전부 불변) — 이번 수정은 **가격축 라벨 plot 2개의 값·색·게이트를 대응 선과 일치**시킨 것뿐입니다. **렌더 방식**: 방향별 `var line` 1개씩(총 **2개**)을 `barstate.islast`에서 매 봉 현재 임계로 갱신하고(`line.new`/`set_xy1·2` + `extend=extend.both`로 pane 전체 수평 연장, 미표시 시 `line.delete`→na), **프라이스 스케일 라벨**은 방향별 `plot(가격, display=display.price_scale)` 라벨 전용 plot(과매수/과매도 라인에서 쓰던 패턴)으로 **대응 선과 동일 값·동일 색**으로 표기합니다. `var line` 2개 재사용이라 **`max_lines_count`(기본 50) 영향 없음**(누적 생성 아님). ⚠️ **전환 표시 게이트와 밴드 배경은 모두 `baseState`(순수 기울기 서열)를 참조합니다** — 배경은 여기에 기울기 3행 컨플루언스(녹/빨강 유무)를 AND로 더할 뿐이라, 전환 표시가 뜨는 상태에서 기울기 컨플루언스가 어긋나면 배경만 안 뜰 수 있습니다(옛 억제/플립 게이트 `paintState`는 제거됨). ⚠️ **현재봉 기준(깜빡임 감수·CEO 인지)**: `xUp`/`xDn`이 확정봉 `[1]` base값(`ribbonE1[1]` 등) + 현재봉 `close`(=`close[0]`) 투영이라 임계가 라이브 봉 동안 갱신 → 선·라벨이 실시간 봉에서 깜빡일 수 있습니다(현재봉[0] 실시간, 과거봉은 확정·비리페인팅, 표시 전용).
- **표시 전용.** 매매 판정·밴드와 무관합니다. `지수 리본 길이`(기본 20)만 전략성 파라미터(수학자 리뷰 대상)이며, 배경 판정 자체엔 별도 임계 입력이 없습니다(기울기 순서만 비교).

## 레이어(z-order) 순서 — 실제 순서(auto-scale 폭발 버그 수정 반영)

차트에 겹쳐 그려지는 페인팅의 **앞뒤(z-order)** 순서입니다. Pine v6의 렌더 순서는 `explicit_plot_zorder=true`(스크립트 상단 `indicator()`에 지정)에서 **`plot()`/`hline()`/`fill()`의 코드 선언 순서**로 결정됩니다(먼저 선언 = 더 뒤, 나중 선언 = 더 앞). **단 `bgcolor()`는 이 인자와 무관하게 항상 최후면 그룹**이고, **`barcolor()`(비정상 캔들 몸통색)는 봉 몸통에 직접 그려져 `plot`/`fill`과 레이어가 다릅니다**. **비정상 매수/매도는 CEO 지시로 배경(`bgcolor`)에서 캔들 몸통색(`barcolor`)으로 전환**됐으므로, 이제 `plot`/`fill` 간 순서는 아래와 같습니다(뒤 → 앞):

1. **가장 뒤(back-most): 거래량 가중선 50/100/200 + 100~200 fill.** `plot`/`fill` 중에서는 가장 먼저 선언되어 나머지 plot/fill보다 뒤입니다.
2. **가장 앞(front-most): 나머지 모든 페인팅.** VWAP 본선·가격축 라벨, 밴드1/밴드2 + 각 fill, 정배열/역배열 및 전환 확정 배경(밴드2 영역 fill), 지수 리본(EMA/DEMA/TEMA), 그리고 프랙탈 삼각형/후보 마커·%R 다이버전스 원(`plotshape`)입니다. `plotshape`와 드로잉(라벨·상태 테이블)은 `explicit_plot_zorder` 영향 밖에서 각자 상위 z-그룹의 최전면을 유지하므로 자동으로 "가장 앞"에 포함됩니다.
3. **레이어 밖(별도): 비정상 매수/매도 캔들 몸통색(`barcolor`).** 봉의 몸통색을 직접 바꾸는 것이라 위 `plot`/`fill` 순서와 별개이며, 밴드 배경(fill)과 대상이 달라 겹쳐도 시각 충돌 없이 공존합니다. 색·조건·판정(`abnBarColor`/`abnShowBg`/`abnCandleState`)은 불변.

⚠️ 이 순서는 **색·조건·판정·값·산식을 일절 바꾸지 않고 렌더 매체(비정상 배경 `bgcolor`→캔들 몸통색 `barcolor`)만** 전환한 결과입니다. **최종 표시는 TradingView 컴파일·실차트에서 재확인이 필요합니다(비정상 캔들색이 몸통에만 적용되고 나머지 봉은 기본색 유지되는지).**

## 윌리엄스 프랙탈 + 각도필터(ratio) + 후보(삼각형/역삼각형) + %R 다이버전스

WILLIAMS-FRACTAL 지표(`williams-fractal.pine`)의 **프랙탈 판정·엄격 모드·%R 다이버전스** 로직·페인팅을 이식하고, 알고리즘 수학자가 설계한 **각도 정교화 2종(로직1 ratio 게이트 + 로직2 후보 마커)**을 신규 구현한 블록입니다. ⚠️ **후보 반투명 배경은 제거됐습니다(본부 지시)** — 후보는 이제 삼각형/역삼각형 마커로만 표시합니다(아래 로직2 참조). 매매 신호가 아니라 **표시 전용 국면 표식**이며, 단일 신호가 아니라 이치모쿠·테이블·보조지표 정렬 확인용으로 설계했습니다(펀드 철학: 단일 신호 불신). 기존 auto-vwap 기능(VWAP·밴드·비정상·리본·테이블)은 전부 불변입니다.

### 1. 확정 프랙탈(양방향, williams-fractal 원본 이식)

- **판정(표준 5봉).** 중심봉 + 좌우 각 `fracN`봉(기본 2 → 총 5봉). **하방(저점) 프랙탈**=중심봉 `low[fracN]`이 좌우 각 봉 저가보다 모두 낮음 → **매수**. **상방(고점) 프랙탈**=중심봉 `high[fracN]`이 최고 → **매도**. 좌측(과거)=`[fracN+i]`·우측(최근)=`[fracN-i]`(i=1..fracN). 함수 `isDownFractal(len)`/`isUpFractal(len)`은 원본과 동일합니다.
- **엄격 모드**(`fracStrictMode`, 기본 **ON**). 표준식을 **인접 봉 단조**(계단식 산/계곡)로 강화합니다 — 상방 좌측 단조상승·우측 단조하강(피라미드), 하방은 부등호 반전(계곡). n=2면 `high[len+2]<high[len+1]<high[len]>high[len-1]>high[len-2]`. OFF면 중심이 좌우보다 높기/낮기만.
- **동시 확정 처리.** 같은 중심봉이 국소 고점이자 저점이면 상방·하방이 동시 확정될 수 있어(드묾), 중심봉 봉 색(`close[fracN]` vs `open[fracN]`)으로 1개만 남깁니다 — **양봉→매수만·음봉→매도만·도지→둘 다 억제**(중립·자본 보존, 동시 확정일 때만 발동).
- **표시·리페인팅.** 확정 삼각형은 `offset −fracN`으로 중심봉에 소급합니다(중심봉 + 우측 `fracN`봉이 모두 나온 뒤 확정 → `fracN`봉 후행). 한 번 확정된 프랙탈은 재계산되지 않고 미래참조(`request.security` lookahead 등)도 없어 **소급 표시는 리페인팅이 아닙니다**.

### 2. 로직1 — 가짜 프랙탈 제거(ratio 대칭 게이트, 알고리즘 수학자 사양)

확정 프랙탈 중 **좌우 비대칭이거나 미세한** "가짜 프랙탈"을 ratio 게이트로 걸러, 게이트를 통과한 프랙탈만 삼각형으로 그립니다. **판정은 대칭비(ratio)만** 쓰고 `degree/atan`은 쓰지 않습니다.

- **정규화 척도.** 프랙탈 전용 `fracAtrN = ta.atr(atrLen)`(`atrLen` 기본 **14**)을 **중심봉 기준으로 얼려** 사용: `atrRef = fracAtrN[fracN]`. (기존 auto-vwap의 `abnAtr`/`ltAtrTable`와 별개 — 변수 접두어 `frac*`로 충돌 회피.)
- **기울기(ATR 정규화).**
  - 고점(매도): `slopeUpRise = (high[fracN] − high[fracN+fracN]) / atrRef`(과거 상승), `slopeUpDrop = (high[fracN] − high[fracN−fracN]) / atrRef`(미래 하강).
  - 저점(매수, 부호 반전): `slopeDnFall = (low[fracN+fracN] − low[fracN]) / atrRef`(과거 하강, 양수), `slopeDnRise = (low[fracN−fracN] − low[fracN]) / atrRef`(미래 상승, 양수).
- **게이트(양방향 대칭).** `유효 = 둘 다 > 0`, `강도 = max(좌,우) ≥ slopeMin`, `대칭비 = min(좌,우)/max(좌,우) ≥ symMin`. 세 조건 AND. `upFractalConfirmedGated = upFractalConfirmed and upGate`, `downFractalConfirmedGated = downFractalConfirmed and dnGate`. 삼각형 plotshape 조건을 이 `*Gated` 값으로 교체했습니다.
- **미세 프랙탈 탈락(CEO 확정).** `slopeMin` 게이트를 **활성**(기본 **0.5**)해 강도가 약한 미세 프랙탈을 탈락시킵니다. `symMin` 기본 **0.5**(범위 0.2~0.9, step 0.05). `atrRef`가 `na`(워밍업)이면 기울기가 `na`가 되어 게이트가 false → 삼각형 미표시(안전).

### 3. 로직2 — 후보(1봉 조기, 삼각형/역삼각형 마커)(알고리즘 수학자 사양 + 본부 지시)

확정보다 **1봉 먼저** 잠정 후보를 잡아 **삼각형/역삼각형 마커**로 예고합니다. ⚠️ **후보 반투명 배경은 제거됐습니다(본부 지시)** — 이전의 원 마커 + `bgcolor` 배경 대신 삼각형/역삼각형 마커만 씁니다.

- **후보 시점·봉당 기울기.** 중심봉=`[1]`·미래 1봉=`[0]`, `atrRefC = fracAtrN[1]`. 과거 구간은 **봉당** 기울기로 환산(`/fracN`), 미래는 1봉 그대로.
  - 고점(매도): `slopeUpRiseC = (high[1] − high[1+fracN]) / atrRefC / fracN`, `slopeUpDrop1 = (high[1] − high[0]) / atrRefC`.
  - 저점(매수, 대칭): `slopeDnFallC = (low[1+fracN] − low[1]) / atrRefC / fracN`, `slopeDnRise1 = (low[0] − low[1]) / atrRefC`.
- **후보 게이트.** 유효(둘 다 > 0) + 강도(`max ≥ slopeMin`) + **완화 대칭비**(`min/max ≥ symMinCand`), `symMinCand = symMin × candRelax`. `candRelax` 기본 **0.7**(확정 0.5 → 후보 **0.35**). 판정식·offset·전이 로직은 **불변**입니다.
- **순수 함수적 전이(리페인팅 최소).** 후보→확정/폐기 전이는 **상태 저장(var 래치) 없이** 매 봉 `[1]`/과거참조로 재계산합니다.
- **마커(삼각형/역삼각형, 배경 제거).** **매수 후보(하방/저점 프랙탈)=삼각형 위**(▲, `shape.triangleup`, `location.belowbar`), **매도 후보(상방/고점 프랙탈)=역삼각형**(▼, `shape.triangledown`, `location.abovebar`), 모두 `offset −1`(중심봉+1). 색은 **확정 프랙탈 색을 공유**(매수=파랑·매도=빨강)하되 **투명도 50**(`후보 마커 투명도 fracCandMarkerTransp`, 기본 **50**)을 적용해 확정 삼각형(`offset −fracN`, 불투명)과 시각 구분합니다(`color.new(fracBuyColor, 50)`/`color.new(fracSellColor, 50)`). 별도 후보 색 input은 없습니다.
- **⚠️ non-repainting 통일(본부 지시).** 후보 삼각형/역삼각형 마커를 `barstate.isconfirmed` 가드(`fracCandBuyShow = fracShowCandidate and dnCandidate and barstate.isconfirmed`, 매도는 `upCandidate`)로 **확정봉에서만 표시**해 실시간 봉 점멸을 없앴습니다. 후보는 여전히 확정(offset −fracN)보다 **1봉 빠르게**(중심봉+1 = offset −1) 뜹니다. 과거봉의 `[1]`/`[1+fracN]`/`[0]` 입력은 확정 후 불변이라 재평가돼도 동일 → 리페인팅이 없습니다.
- **양방향 대칭.** 상승 반전(저점 매수)·하락 반전(고점 매도) 모두 대칭 적용.

### 4. 윌리엄스 %R 다이버전스(williams-fractal 원본 이식)

- **%R.** `wpr = ta.wpr(wprLen)`(기본 14, 종가 기준, 범위 −100~0). 오버레이 부적합이라 **라인은 그리지 않고** 다이버전스 봉에 **원 마커**(`offset 0`, 확정된 현재봉)만 표시합니다.
- **강세(매수)=녹 원(belowbar).** `wpr[1] < wprLower`(직전 봉 하단 밴드 진입, 기본 −80) AND (`close < close[1]` AND `wpr > wpr[1]`) — 과매도 진입 후 종가↓·%R↑.
- **약세(매도)=노랑 원(abovebar).** `wpr[1] > wprUpper`(직전 봉 상단 밴드 진입, 기본 −20) AND (`close > close[1]` AND `wpr < wpr[1]`) — 과매수 진입 후 종가↑·%R↓.
- **레이어·리페인팅.** 원은 프랙탈 삼각형보다 **먼저** 호출해 아래 레이어(뒤)로 그려지고, 겹치면 삼각형이 앞에 보입니다. `close[1]`·`wpr[1]`·`wpr` 모두 확정/과거참조라 **리페인팅이 없습니다**.

⚠️ **컴파일 확인 필요.** 로컬 Pine 컴파일러가 없어 정적 리뷰(타입·`na`·`max_bars_back`·plot 개수 상한)로 검증했으며, 최종 동작은 **TradingView 컴파일·차트 확인**이 필요합니다.

## 주의사항

- 이 지표는 거래량 데이터가 있어야 정상 동작합니다. 코드에는 거래량이 없을 때 `runtime.error`도 들어 있습니다.
- VWAP 누적은 **Recent Bars 롤링 단일 방식**으로 고정입니다(앵커모드·세션/거래일 기준 제거).
- `Recent Bars`는 차트 타임프레임의 봉 수 기준이라, 타임프레임을 바꾸면 같은 숫자여도 의미가 달라집니다.
- 저유동 종목에서는 VWAP과 밴드 반응이 더 거칠 수 있습니다.
- 성능: 헤더에 `max_bars_back=1000`을 두어(원본 이치모쿠와 동일 헤드룸) `ta.vwma(close, 200)`+σ 등 200봉 참조의 런타임 오프셋 오류·버퍼 자동확장을 예방합니다(산식 변경 아님).
